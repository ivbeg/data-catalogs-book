# Статические сайты

Статический сайт — это набор готовых страниц. Их собирают из файлов (часто из Git-репозитория) и кладут на хостинг, который умеет только отдавать файлы: GitHub Pages, GitLab Pages и аналоги. Отдельной базы и круглосуточного приложения нет. Поэтому ломаться почти нечему, а забрать сайт к себе — значит скопировать файлы.

## Готовые инструменты

**JKAN** собирает каталог на Jekyll. Набор описывают файлом, сайт отдаёт страницу набора и общий `data.json`. Лицензия MIT. В реестре dataportals-registry на 9 октября 2026 года (выпуск 1.26.0 от 6 октября) таких каталогов около пятидесяти. Подходит для десятков наборов. Не подходит, когда нужны роли и форма «добавить набор» для людей без Git. Живой каталог на JKAN — [opendata.scot](https://opendata.scot).

**PortalJS** — набор средств на Next.js, чтобы собрать портал данных, в том числе поверх файлов и чужих API. Тяжелее JKAN. Имеет смысл, если нужен более сложный интерфейс, но свою базу вы всё ещё не хотите сопровождать как CKAN.

**OpenSDG** — статический сайт показателей целей устойчивого развития. В реестре около семидесяти таких сайтов. Это не общий портал файлов, а витрина показателей. Обмен SDMX там не ядро, а дополнительная возможность: для национальной статистической службы смотрите PxWeb или .Stat, а OpenSDG — для понятной публичной витрины. Так устроены [показатели ЦУР Великобритании](https://sdgdata.gov.uk/).

**Статический каталог STAC** — JSON-файлы, которые описывают снимки, растры и другие пространственные файлы. Его можно положить в облачное хранилище. Отдельный сервер каталога не нужен, пока каталог читают программы, понимающие STAC.

**Обычный генератор страниц** (Hugo, Jekyll, Astro и другие) достаточен, если наборов мало. Возьмите шаблон страницы, вставьте разметку schema.org из [готового файла](pathname:///templates/schema-dataset.jsonld) и положите рядом `data.json` или `datapackage.json`.

**Datasette** стоит рядом, но это не чистая статика: одна команда публикует базу SQLite с веб-страницей и JSON API. Удобно для одной большой таблицы. В реестре около сорока пяти таких сайтов. Сопровождение проще портала, но процесс всё же должен работать.

## Как это выглядит в жизни

Статика годится не только для маленькой лаборатории. Два примера показывают, как далеко можно зайти без своего сервера каталога.

**Национальный портал Чехии.** Информационная часть [data.gov.cz](https://data.gov.cz/) — статьи, инструкции, стандарты публикации — по описанию в [репозитории сайта](https://github.com/datagov-cz/data.gov.cz) собрана генератором Jekyll и публикуется через GitHub Pages. Правку текста можно предложить запросом на изменение (pull request), как в любом открытом проекте. Сам каталог наборов — отдельное приложение: оно показывает описания из хранилища связанных данных, а к хранилищу открыта точка запросов SPARQL. Связанные данные (Linked Data) — способ публиковать описания так, чтобы каждая запись и каждое значение имели свой адрес и на них можно было ссылаться из других систем.

Файлов портал не хранит вовсе. Он собирает описания из местных каталогов ведомств и городов, а ссылки ведут на их серверы. 12 октября 2026 года точка SPARQL насчитала около 31 тысячи наборов из примерно 130 каталогов, и все адреса скачивания вели на сайты публикаторов, а не на data.gov.cz. Число наборов при этом меняется сильнее, чем сами данные: в феврале 2023 года их было 142 тысячи, из них 137 тысяч давала одна кадастровая служба. Плата за такую лёгкость — портал не может сохранить копию, если ведомство удалит файл. Почему это важно, разобрано в главе [о хранилище](../04-features/05-data-storage.md).

**Портал, который собрало сообщество.** В Шотландии долго не было общего государственного портала открытых данных, хотя свои порталы были у городов, ведомств и университетов. Волонтёры сделали [opendata.scot](https://opendata.scot): сайт на JKAN, описания и сборщики лежат [на GitHub](https://github.com/OpenDataScotland), сбор запускается по расписанию через GitHub Actions. Скрипты забирают описания с порталов на CKAN, ArcGIS и других платформах и складывают их файлами в репозиторий. В мае 2023 года там было 1887 наборов примерно из двадцати источников, на 9 октября 2026 года — около 2,6 тысячи файлов описаний, обновление шло раз в одну-две недели. На сайте есть раздел аналитики: какие ведомства публикуют данные и на каких платформах работают их порталы.

Стоит такой портал почти ничего: хостинг бесплатный, сервер не нужен. Риск заброшенного движка тоже невелик. С 2018 по 2022 год в [JKAN](https://github.com/timwis/jkan) не было ни одного изменения, но сайт из готовых файлов от этого не ломается. Потом разработка возобновлялась в 2023 и 2026 годах, в 2026-м добавили, например, карту сайта для поисковиков. Позже правительство Шотландии сделало свой поисковик по данным — он разобран в главе [о поисковиках и агрегаторах](../03-types/09-search-engines-aggregators.md).

## Что сделать обязательно

- Отдельная страница у каждого набора, адрес которой не меняется при правке опечатки.
- Разметка schema.org/Dataset на этой странице.
- Один файл со всеми описаниями (`data.json` или набор файлов Frictionless).
- `sitemap.xml`, чтобы поисковик увидел страницы.
- Лицензия на странице набора.

Без этих пунктов сайт остаётся списком ссылок. С ними он закрывает минимум из [чек-листа](../06-choice/07-requirements-checklist.md).

## Чего статический сайт не даст

Ролей, заявки на закрытый файл, сбора чужих каталогов по расписанию и API поиска по тысячам наборов. Если это стало обязательным, способ создания пора менять, а не наращивать самодельный сервер вокруг генератора страниц.
