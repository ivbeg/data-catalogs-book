# Как сделать публикацию находимой

Набор, который лежит «где-то в репозитории», не опубликован. Опубликован набор, у которого есть страница, лицензия и описание, понятное и человеку, и программе.

Ниже один сквозной путь для набора среднего размера. Большой файл отличается только местом байтов: они в облаке, описание — всё равно на странице.

## Путь от файлов до ссылки, которую можно дать в тексте

1. Заведите репозиторий. Положите туда шаблоны: [README](pathname:///templates/README.md), [datapackage.json](pathname:///templates/datapackage.json), [CITATION.cff](pathname:///templates/CITATION.cff), лицензию и файл в `data/`.
2. Включите сайт из этого репозитория (GitHub Pages или аналог). На странице набора вставьте разметку из [schema-dataset.jsonld](pathname:///templates/schema-dataset.jsonld) — блок `application/ld+json` в странице. Адрес страницы не должен меняться при правке описания.
3. Проверьте разметку во [внешнем тесте расширенных результатов](https://search.google.com/test/rich-results). Ошибки в типе Dataset исправьте до того, как звать людей по ссылке.
4. Зафиксируйте версию меткой и, если на данные будут ссылаться, подключите архивацию выпусков в Zenodo. Полученный DOI впишите в `CITATION.cff` и в разметку.
5. Сообщите о странице туда, где ваши пользователи и так ищут: региональный или ведомственный портал, отраслевой каталог, реестр каталогов. Одной регистрации в поисковике мало, если национальный портал собирает только тех, кто отдаёт ему файл описаний.
6. Через несколько недель проверьте, находится ли название набора в Google Dataset Search. Если нет, сначала перепроверьте разметку и то, что страница открыта без входа, а не смену площадки.

## Минимум, без которого путь не работает

- [ ] Страница с постоянным адресом и понятным описанием.
- [ ] Лицензия рядом с данными.
- [ ] Разметка schema.org/Dataset, чтобы страницу нашли человек и поисковик.
- [ ] Файл в том профиле, который забирает верхний портал, если набор должен попасть в федерацию.
- [ ] `datapackage.json`, чтобы по файлу было понятно, какая это таблица и что в колонках.
- [ ] Дата обновления и контакт.

API поиска, личный кабинет и карта на главной в этот минимум не входят.

## Чего не делать

- Не выкладывать только PDF со сканом таблицы.
- Не ставить капчу на страницу описания.
- Не менять адрес страницы, когда поправили заголовок. Поисковик и чужие статьи запомнили старый.
- Не писать «данные по запросу» без описания, что именно запрашивают. Описание открыто всегда, ограничивать можно файл.
