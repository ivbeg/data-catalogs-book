# Как сделать публикацию находимой

Набор находят по странице с постоянным адресом. Человек читает на ней описание и лицензию, поиск по данным читает разметку, сборщик каталога забирает отдельный файл, а ссылка из отчёта ведёт на выпуск с DOI. Репозиторий, запись в Zenodo и карточка в чужом каталоге называют тот же набор и ведут на эту страницу.

Ниже порядок для одного набора среднего размера. Как устроены сами площадки — в главах [о статическом сайте](./02-static-sites.md), [о Git](./03-git-repositories.md) и [об облаке и хабах](./04-cloud-storage-and-hubs.md). Как то же самое платформа делает для тысяч страниц — в главе [о находимости каталога](../07-publishing/05-discoverability.md).

## Кто ищет и что он читает

Одного файла в открытом доступе мало: у каждого читателя свой вход.

| Кто ищет | Что открывает | Что для него готовят |
|----------|---------------|----------------------|
| Человек со ссылкой | страницу | описание, лицензия, файл, дата, контакт |
| Обычный поисковик | HTML и ссылки с других сайтов | текст на странице и карта сайта |
| Поиск по данным, например Google Dataset Search | разметку на странице | schema.org типа Dataset, которую можно прогнать тестом |
| Сборщик национального или ведомственного каталога | файл в профиле, о котором вы договорились | `data.json` или DCAT-AP, с заполненными полями этого профиля |
| Автор отчёта или статьи | выпуск, который не меняется задним числом | метку версии и DOI этого выпуска |

Темы репозитория `dataset` и `open-data` помогают тем, кто ищет репозитории на самой площадке. Поиск по данным их не читает. Почему так устроен GitHub — в главе [о репозиториях](./03-git-repositories.md#почему-репозиторий-почти-не-ищут).

## Один главный адрес

Когда мест несколько, у набора всё равно один главный адрес: страница, которую ведёте вы. Остальные адреса на неё опираются.

| Поле разметки | Куда смотрит |
|---------------|--------------|
| `url` | главная страница |
| `identifier` | DOI выпуска, после того как номер выдан |
| `sameAs` | другая страница того же набора, например запись Zenodo |
| `includedInDataCatalog` | каталог, в котором запись уже появилась |

Google просит ставить полную разметку на главную страницу. Если разметка стоит и на копии, у копии в `sameAs` лежит адрес главной. Одно и то же значение `sameAs` у двух разных наборов склеивает их в один. Адрес поиска, ветки `main` и списка файлов в `sameAs` не ставят: это не страница набора.

Адрес страницы не собирают из заголовка. Заголовок правят, путь остаётся: `…/bus-stops`. Старые ссылки из статей и из индекса поисковика помнят путь, а не сегодняшнее название.

Поле `includedInDataCatalog` заполняют после того, как сборщик опубликовал запись. Имя каталога в разметке до этого обещает карточку, которой нет.

## Что поставить на страницу

Разметка — блок `application/ld+json` в HTML страницы. Готовый текст лежит в [schema-dataset.jsonld](pathname:///templates/schema-dataset.jsonld). Его вставляют в шаблон страницы. В README на github.com тот же текст остаётся абзацем для человека: тега `script` там нет, и поиск по данным его не читает.

Документация Google, сверенная 14 октября 2026 года, требует у типа Dataset два поля: `name` и `description`. Описание — от 50 до 5000 знаков. Более длинный текст поиск обрезает на 5000. Одно короткое предложение часто не дотягивает до 50. В описании пишут, что в таблице, за какой период и территорию, кто собрал и как часто файл меняется.

Остальные поля Google называет рекомендуемыми. Без них тест может пройти, а пользоваться набором нельзя. Лицензию, издателя и прямую ссылку на файл просят ещё и потому, что тип Dataset ставят и на мусор: об этом в главе [о находимости каталога](../07-publishing/05-discoverability.md#разметка-есть-и-у-спама).

| Поле | Что писать |
|------|------------|
| `name` | название, по которому этот набор отличить от соседнего |
| `description` | от 50 до 5000 знаков, тот же смысл, что в тексте страницы |
| `license` | ссылка на конкретную версию, например CC BY 4.0. Ссылка на CC BY без номера версии для Google слабее |
| `distribution` с `contentUrl` | прямая ссылка на файл и его `encodingFormat`. Ссылка на раздел сайта файлом не является |
| `creator`, `publisher` | кто собрал и кто издаёт |
| `dateModified` | дата файла. Её меняют в тот день, когда меняется файл |
| `temporalCoverage`, `spatialCoverage` | период в виде `2020-01-01/2025-12-31` и территория. Если периода или территории нет, строки из шаблона удаляют |
| `identifier` | DOI. В шаблоне книги этого поля нет: его добавляют после выдачи номера |
| `sameAs` | вторая страница того же набора |

Google пишет, что понимает на странице и schema.org, и DCAT. Проверка расширенных результатов принимает schema.org. Пример DCAT в той же документации помечен как неподдерживаемый тестом. Поэтому на своей странице ставят JSON-LD: его можно проверить до того, как давать ссылку людям. Атрибуты `dcat:Dataset` на странице JKAN этот тест не подтверждают. Файл `data.json` для сборщика — отдельный документ, его Google со страницы не читает.

Словарь колонок для людей и программ лежит в `datapackage.json`. Google отдельно называет экспериментальной разметку CSVW прямо на странице и предупреждает, что тест на такой блок ругается. Для таблицы хватает CSV по прямой ссылке и описателя пакета.

Страница отдаёт этот HTML сама, без входа и без капчи. Оболочка, которую дорисовывает скрипт в браузере, для робота пуста. Как это выглядит у больших сайтов — в главе [о находимости каталога](../07-publishing/05-discoverability.md#что-поисковик-не-видит).

## Карта сайта

Google просит карту сайта, чтобы находить адреса наборов, и `sameAs`, чтобы понимать, где копии. У одного набора в карте одна строка. У каталога из десятков страниц без карты робот может не дойти до каждой.

Файл `robots.txt` поисковик читает только из корня имени сайта. Так сказано в [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309), и тот же предел разобран на геопорталах в главе [о находимости каталога](../07-publishing/05-discoverability.md#что-поисковик-не-видит). У адреса `https://имя.github.io/bus-stops/` корень — `https://имя.github.io/robots.txt`. Файл `robots.txt` внутри каталога `bus-stops` этим правилом не является. Если корнем вы не распоряжаетесь, отдельный запрет из вашего каталога не появится. Карту тогда отправляют в [Google Search Console](https://search.google.com/search-console/about) по полному адресу `sitemap.xml`.

GitHub Pages сам разметку Dataset и карту сайта не пишет. Оба файла кладут в сборку сайта. Пределы хостинга и готовые генераторы — в главе [о статических сайтах](./02-static-sites.md).

## Файл для сборщика

Разметка одной страницы в национальный каталог не попадает. Сборщик забирает файл в том профиле, который принимает сейчас, а не в самой новой редакции схемы. data.gov по-прежнему собирает и DCAT-US 1.1, хотя версия 3.0 уже опубликована. Какой язык кому отдают — в главе [о стандартах](../07-publishing/02-metadata-standards.md).

Файл готовят, когда сборщик есть и вы подали ему адрес. Регистрация сайта в Search Console этот адрес сборщику не сообщает. Как подать каталог на сбор — в главе [о федерациях](../07-publishing/03-federation-and-harvesting.md).

Файл, который объявляет схему и молчит об обязательных полях, сборщик может забрать таким, какой он есть. Короткий `data.json` у JKAN и записи без лицензии у небольшого ведомства разобраны в главах [о статических сайтах](./02-static-sites.md#jkan) и [«Когда портал не нужен»](./01-when-portal-not-needed.md#файл-на-своём-сайте-вместо-портала). Если сборщика нет, отдельный файл ради строки `conformsTo` не заводят: страница с разметкой уже описывает набор.

## Вторая страница с DOI

DOI нужен, когда на выпуск ссылаются в тексте. Для внутренней таблицы его не заводят. Как связать репозиторий GitHub с Zenodo и почему `.zenodo.json` перекрывает `CITATION.cff` — в главе [о репозиториях](./03-git-repositories.md#выпуск-и-doi). Пока номера нет, блок `identifiers` из шаблона `CITATION.cff` удаляют.

Запись Zenodo с типом «набор данных» сама становится страницей с разметкой Dataset. DataCite пишет, что в Google Dataset Search попадают посадочные страницы с классом Dataset, а согласование содержимого по DOI — только если запись в состоянии Findable и тип ресурса Dataset. Сроком, когда Google дойдёт до страницы, DataCite не распоряжается. Тип «программа» этот класс не получает: в `.zenodo.json` для данных ставят `upload_type` со значением `dataset`.

Живая запись показывает, что страница Zenodo и ответ по DOI — два разных документа. 14 октября 2026 года выпуск Cantometrics, DOI [10.5281/zenodo.4898406](https://doi.org/10.5281/zenodo.4898406), отдал в HTML один блок JSON-LD. Обычный запрос страницы вернул код 200. Тот же адрес с заголовком браузера `Mozilla/5.0` вернул 403: отказ относится к этому заголовку, а не к отсутствию страницы.

- Тип в разметке страницы — `https://schema.org/Dataset`. Короткого слова `Dataset` сразу после кавычки там нет.
- Видимый текст описания — «The data repository for the Cantometrics dataset», 48 знаков. Строка в разметке длиннее, 56 знаков, только из-за тегов абзаца. Порог Google — от 50 знаков самого описания.
- `license` ведёт на текст CC BY-NC 4.0. В репозитории той же метки файл лицензии — CC BY 4.0. Расхождение уже разобрано в главе [«Когда портал не нужен»](./01-when-portal-not-needed.md#три-места-сразу).
- `url` — `https://zenodo.org/records/4898406`. Поля `sameAs` нет.
- `contentUrl` ведёт на ZIP выпуска. Запрос заголовков этого адреса вернул код 200 и тип `application/octet-stream`. В разметке у файла указан `application/zip`.

Запрос JSON-LD по тому же DOI в тот день вернул другой документ: тип Dataset, описание из 48 знаков, без ссылки на файл. Поле `url` в нём — старый путь `/record/4898406`, он отвечает кодом 301 и уводит на `/records/4898406`. Адрес метки в GitHub этот ответ называет статьёй, на которой набор основан, а не второй страницей набора.

Отсюда практический вывод. DOI и страница Zenodo закрывают ссылку из отчёта и дают поиску по данным ещё одну страницу. Текст описания, лицензию и прямую ссылку держат на своей странице и в запись Zenodo копируют теми же. В `identifier` своей разметки ставят DOI выпуска. В `sameAs` — адрес записи Zenodo. В цитате используют DOI выпуска, а общий DOI всех версий оставляют тем, кому нужна последняя.

## Порядок на одном наборе

Пример — расписание автобусов района. Имена вымышленные, файлы — [шаблоны этой книги](pathname:///templates/README.md). Рядом можно открыть живой репозиторий [Country Codes](https://github.com/datasets/country-codes): у него другая тема, описатель называется `datapackage.yml`, а 14 октября 2026 года в HTML страницы репозитория не было блока JSON-LD.

1. **Репозиторий.** Положите шаблоны: README, `datapackage.json`, `LICENSE`, таблицу в `data/`. В `CITATION.cff` оставьте `type: dataset` и удалите блок `identifiers`, пока DOI нет. В README напишите, что это за расписание, за какой сезон, кто отвечает и как часто файл меняется. Темы `dataset` и `open-data` поставьте: они помечают репозиторий на площадке. Что ещё лежит в пакете и где кончаются пределы Git — в главе [о репозиториях](./03-git-repositories.md).

2. **Страница.** Соберите сайт из этого репозитория или положите страницу на уже существующий сайт. Путь `…/bus-stops` не меняется вместе с заголовком. В HTML вставьте блок из шаблона разметки. Описание сделайте длиннее 50 знаков, например: «Расписание остановок и времени отправления автобусов района за сезон: остановка, маршрут и время. Файл обновляют раз в сезон.» Лицензия — ссылка на CC BY 4.0. В `contentUrl` — прямая ссылка на CSV. Поле `identifier` пока не добавляйте.

3. **Проверка разметки.** Адрес страницы вставьте в [проверку расширенных результатов](https://search.google.com/test/rich-results). Ошибки типа Dataset исправьте до того, как давать ссылку. Страница должна открываться без входа: иначе тест и поисковик видят заглушку.

4. **Карта сайта.** Положите `sitemap.xml` с адресом этой страницы. Если распоряжаетесь корнем имени сайта, укажите карту в `robots.txt` этого корня. Иначе отправьте полный адрес карты в Search Console.

5. **Версия и DOI.** Если на расписание будут ссылаться, поставьте метку, например `v2026.1`, и получите DOI выпуска. Номер впишите в `CITATION.cff` на ветке и в `identifier` разметки. В `sameAs` поставьте адрес записи Zenodo. Лицензия в `LICENSE`, в описателе, на странице и в записи Zenodo — одна и та же. Для таблицы, на которую никто не ссылается, шаг пропускают.

6. **Сборщик.** Если региональный или национальный каталог забирает файл, положите его в профиле, который каталог принимает, и подайте адрес. Поля, которые профиль считает обязательными, заполните до заявки.

7. **Через несколько дней и ещё раз через несколько недель.** Найдите название в [Google Dataset Search](https://datasetsearch.research.google.com/). Google пишет, что обход занимает несколько дней, а исчезновение из выдачи — дни или недели. Раньше этого срока площадку не меняют. Сначала перепроверьте тест разметки и то, что страница открыта без входа.

## Пример: главный адрес на своей странице

**Контекст.** Двое уже ведут квартальную таблицу в репозитории. Раз в год ставят выпуск и получают DOI. Национальный каталог организацию не собирает. Через месяц по названию таблицу не находят в поиске по данным. Один участник предлагает давать ссылку на репозиторий, другой — только DOI, третий — поставить портал.

**Варианты.** Вкладка репозитория на github.com. Только запись Zenodo. Своя страница с разметкой, DOI в `identifier` и адресом Zenodo в `sameAs`. Портал.

**Критерии.** Разметку можно проверить до индексации. Ссылка из отчёта открывает неизменный выпуск. Человек без DOI открывает описание и файл. Сопровождение остаётся у этих двоих.

**Решение.** Главный адрес — своя страница. DOI выпуска стоит в отчёте и в поле `identifier`. Запись Zenodo — вторая страница того же набора.

**Почему.** Вкладка github.com у репозитория со словарём колонок не содержит Dataset: 14 октября 2026 года так открылась страница Country Codes. Запись Zenodo тип Dataset ставит сама, но описание и лицензию берёт из того, что ей отправили. У Cantometrics видимый текст короче порога Google, а лицензия на странице Zenodo разошлась с файлом в репозитории. Портал добавляет сервер при одном наборе и двух публикаторах.

**Последствия.** Карту сайта и разметку обновляют вместе с файлом. Пустой DOI не публикуют. Поиск по данным может сначала показать страницу Zenodo: у неё тоже тип Dataset. После индексации своей страницы обе страницы связаны через `identifier` и `sameAs`.

**Когда пересмотреть.** Наборов стало больше, чем двое успевают размечать. Появился сборщик и назвал профиль файла. Описание или лицензия на своей странице и в Zenodo разошлись.

Как записать такую карточку у себя — в главе [«Как обосновать решение»](../06-choice/04-justifying-decisions.md). Выбор репозитория для этой таблицы — в главе [о Git](./03-git-repositories.md#пример-квартальная-таблица-двоих).

## Как проверить

Проверка своей страницы занимает несколько минут. Подставьте её адрес.

```bash
PAGE=https://example.org/bus-stops

# Страница открывается без входа
curl -sI -o /dev/null -w "%{http_code}\n" -L "$PAGE"

# В HTML есть тип Dataset: и короткое имя, и полный адрес schema.org
curl -sL "$PAGE" | grep -o '"@type"[[:space:]]*:[[:space:]]*"[^"]*Dataset"' | head -1
```

Код 200 и строка с `Dataset` значат, что страница отдаёт разметку. Дальше адрес вставляют в проверку расширенных результатов: документация Google требует у описания от 50 до 5000 знаков, и тест сверяет разметку с этими правилами. Пустого `identifier` в блоке быть не должно.

Команды ниже сняты 14 октября 2026 года с чужих публикаций. Они показывают разрыв, а не образец.

```bash
# Страница репозитория открывается. Блока JSON-LD в ней нет: вывод пустой
curl -sL -o /dev/null -w "%{http_code}\n" "https://github.com/datasets/country-codes"
curl -sL "https://github.com/datasets/country-codes" | grep -o 'application/ld+json' | head

# JSON-LD по DOI: тип Dataset, старый путь /record/, без distribution
curl -sL -H "Accept: application/ld+json" "https://doi.org/10.5281/zenodo.4898406"

# Старый путь перенаправляет на /records/
curl -sI -o /dev/null -w "%{http_code}\n" "https://zenodo.org/record/4898406"

# Страница Zenodo: код и тип Dataset в HTML
curl -sL -o /dev/null -w "%{http_code}\n" "https://zenodo.org/records/4898406"
curl -sL "https://zenodo.org/records/4898406" | grep -o '"@type"[[:space:]]*:[[:space:]]*"[^"]*Dataset"' | head -1

# API записи и файл из contentUrl
curl -sL "https://zenodo.org/api/records/4898406"
curl -sI -L -o /dev/null -w "%{http_code}\n" \
  "https://zenodo.org/api/records/4898406/files/theglobaljukebox/cantometrics-v0.1-alpha.zip/content"
```

В тот день страница Country Codes вернула 200, поиск `application/ld+json` ничего не нашёл. Ответ по DOI был типом Dataset. Путь `/record/4898406` вернул 301. Страница `/records/4898406` вернула 200, а поиск типа нашёл `"@type": "https://schema.org/Dataset"`. API записи вернул 200 и тип `dataset`. Заголовки файла из `contentUrl` вернули 200 и тип `application/octet-stream`. Запрос этой же страницы с заголовком `Mozilla/5.0` вернул 403.

## Где путь ломается

- **Вкладка репозитория вместо страницы.** Файл и README на месте, типа Dataset в HTML нет. Обычный поиск может найти README. Поиск по данным ищет разметку.
- **Описание короче 50 знаков.** Тип Dataset объявлен, обязательное поле по правилам Google не заполнено. Теги вокруг короткой фразы длину текста не заменяют.
- **Пустой или вымышленный DOI.** Номер-заглушка из `CITATION.cff` попадает в чужие ссылки. Пока номера нет, блока `identifiers` и поля `identifier` нет.
- **Один `sameAs` у двух наборов.** Поиск склеивает разные таблицы в одну запись.
- **`contentUrl` ведёт на раздел сайта.** Скачивать нечего. В поле стоит адрес файла.
- **Файл объявляет профиль и пропускает его поля.** Сборщик публикует дырявую карточку. Без сборщика такой файл не заводят.
- **Три места с тремя лицензиями.** Человек по DOI и человек по репозиторию получают разные условия. Лицензию пишут один раз и копируют.
- **Капча, вход или страница из скрипта.** Тест разметки и робот видят заглушку. Через месяц индекс будет пуст по той же причине.

## Чем этот путь отличается от портала

Портал сам собирает выгрузку, карту сайта и часто разметку для каждой страницы. Здесь это делает автор страницы, по одному набору. Проверка та же, что в главе [о находимости каталога](../07-publishing/05-discoverability.md): адрес открыт, разметка проходит тест, карта сайта известна поисковику, нужный профиль отдан сборщику. Когда наборов становится больше, чем один человек успевает описывать, или сбор идёт по расписанию из многих организаций, возвращайтесь к главе [«Когда портал не нужен»](./01-when-portal-not-needed.md): порог там записан заранее.
