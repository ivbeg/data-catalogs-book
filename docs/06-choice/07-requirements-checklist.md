# Чек-лист требований

Пункт без ссылки на объяснение превращается в строчку, которую копируют из чужого задания. Ниже у каждого пункта есть глава, где сказано, когда без него можно обойтись.

В задании у пункта три пометки: обязательно, желательно, не нужно — и одна фраза, откуда потребность. Пустое «обязательно» на всё подряд делает сравнение платформ бессмысленным.

## Минимум для любого способа публикации

Даже для статического сайта из десятка наборов.

- [ ] Постоянный адрес каждого набора и файла — [идентификаторы](../04-features/06-identifiers-and-doi.md). Обязательно всем.
- [ ] Лицензия на каждый набор, не только на сайт — [лицензии](../07-publishing/04-licenses-and-access.md). Обязательно всем.
- [ ] Файл со всеми описаниями — [экспорт метаданных](../04-features/02-metadata-export.md). Обязательно порталу и желательно небольшому сайту.
- [ ] Карта сайта sitemap и разметка schema.org — [экспорт метаданных](../04-features/02-metadata-export.md). Обязательно, если набор должны найти поиском.
- [ ] Дата обновления и периодичность — [полнота метаданных](../04-features/03-metadata-depth.md). Обязательно, если данные обновляют.
- [ ] Контакт ответственного. Обязательно всем.
- [ ] Описания читаются без регистрации и капчи — [API и выгрузка](../04-features/04-access-interfaces.md). Обязательно всем, кого могут собирать автоматически.

## Включать, только если есть задача

- [ ] API поиска — обязательно, когда наборов сотни и больше. Не нужно статическому сайту.
- [ ] Своё хранилище файлов и API к таблицам — [хранилище](../04-features/05-data-storage.md). Обязательно научному репозиторию (файлы). Желательно порталу открытых данных. Не нужно геопорталю, который ссылается на сервисы.
- [ ] DOI и версии — [идентификаторы](../04-features/06-identifiers-and-doi.md). Обязательно научному репозиторию. Не нужно оперативным данным.
- [ ] Экспорт цитирования — [цитирование](../04-features/07-citation.md). Обязательно научному репозиторию. Желательно, если на данные ссылаются в аналитике.
- [ ] Свои поля и несколько языков — [полнота метаданных](../04-features/03-metadata-depth.md). Обязательно, если этого требует закон или страна. Иначе желательно или не нужно.
- [ ] Роли, модерация, ограниченный доступ — [доступ и процессы](../04-features/08-access-control-and-workflow.md). Роли обязательны, когда публикует больше одной команды. Ограниченный доступ обязателен для микроданных и чувствительных файлов.
- [ ] Сбор чужих каталогов — [другие возможности](../04-features/10-other-capabilities.md). Обязательно региональному и национальному порталу. Не нужно ведомству, которое публикует только своё.

## По типу каталога

- Геопортал: каталог ISO 19115 и сервис CSW или OGC API Records; слой можно скачать или честно сказано, что доступен только просмотр.
- Научный репозиторий: DOI, версии, OAI-PMH, экспорт цитирования.
- Каталог показателей: SDMX или другой машинный доступ к таблице, описание методики.
- Каталог микроданных: уровни доступа, описание исследования, журнал заявок.

## Когда сравниваете платформы

- [ ] У каждой обязательной функции пометка: ядро, какое расширение и кто его сопровождает, доработка или невозможно — [от функций к платформе](./03-from-features-to-platform.md).
- [ ] Посчитано, сколько расширений придётся проверять при обновлении.
- [ ] Написано, как забрать данные и сохранить адреса, если способ создания придётся сменить — [стоимость ухода](./05-build-or-buy.md).

## После запуска

- [ ] Кто-то следит, что ссылки и сервисы открываются.
- [ ] Открытая регистрация выключена, если внешние люди не публикуют, или включена модерация — [доступ и роли](../04-features/08-access-control-and-workflow.md). Обязательно для порталов, обновлённых со старых версий CKAN.
- [ ] Есть план закрытия: куда денутся данные и какие адреса будут перенаправлять — [жизненный цикл](../09-practices/03-lifecycle.md).
- [ ] Каталог можно найти извне: регистрация в профильных реестрах и разметка, а не только новость на сайте.
