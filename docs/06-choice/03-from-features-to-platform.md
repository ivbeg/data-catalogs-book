# От функций к платформе

Список функций уже есть. Теперь его сравнивают с платформами, а не наоборот.

## Шаг 1. Модель создания

Сначала не марка, а способ: чужой каталог, статический сайт, облачный сервис, свободное ПО, своя разработка. Критерии — в главе [«Свои силы, свободное ПО или облачный сервис»](./05-build-or-buy.md). Если данных мало и команды нет, сравнение CKAN с Dataverse не нужно: публикуйте в существующий каталог.

## Шаг 2. Короткий список

Две-четыре платформы того класса, который совпал с типом данных и способом создания. Ориентир — [классы ПО](../05-platforms/01-software-classes.md) и [карточки](../05-platforms/04-platform-profiles.md).

## Шаг 3. Матрица

По каждой обязательной и желательной функции поставьте одну из четырёх пометок:

- **ядро** — есть в самой платформе;
- **расширение** — есть в названном модуле, и вы проверили, кто его сопровождает и с какой версией ядра он работает;
- **доработка** — в платформе есть куда это встроить, объём оценивает разработчик;
- **невозможно** — платформа так не умеет и не расширяется.

Платформа, у которой обязательная функция «невозможно», выбывает. Остальных сравнивают по цене запуска и сопровождения, а не по числу галочек.

«Доработка» и «невозможно» относятся только к этому сравнению. Сводка по платформам в [приложении](../12-appendices/03-platform-tables.md) пользуется другими словами: ядро, расширение, нет, не проверено. Их не переносят из одной таблицы в другую.

Сокращённый пример для регионального портала открытых данных. Полная таблица — в [приложении](../12-appendices/03-platform-tables.md).

| Функция | CKAN | OpenDataSoft или Socrata | Свой сайт на генераторе |
|---------|------|--------------------------|-------------------------|
| Выгрузка DCAT-AP | расширение ckanext-dcat | ядро | доработка шаблона |
| API поиска | ядро | ядро | невозможно без отдельной программы |
| Свои поля под закон | расширение ckanext-scheming | нет (не произвольная схема) | доработка |
| Сбор каталогов муниципалитетов | расширение ckanext-harvest | не проверено | невозможно |
| DOI | расширение; текущая линейка ядра не подтверждена | нет | нет |

У облачного сервиса произвольной схемы полей нет. Сбор чужих каталогов в этой сверке стоит как «не проверено»: перед договором нужно спросить, на каком тарифе он есть. Если DOI в этом примере не обязателен, CKAN остаётся в списке. Если DOI обязателен, CKAN для этой задачи плохая основа: берите научный репозиторий, а не «CKAN плюс неизвестное расширение».

## Шаг 4. Проверка на живых данных

Поставьте пилот или откройте демонстрационный стенд и опубликуйте пять-десять настоящих наборов, включая неудобный: без лицензии в источнике, с большим файлом, с ежедневным обновлением. Затем проверьте так, как написано в главах о возможностях: выгрузка DCAT, разметка schema.org, постоянный адрес, скачивание файла.

Пилот на демонстрационных данных поставщика эту проверку не заменяет.

## Когда оправдана своя разработка

Одновременно верны все четыре утверждения:

- ни одна платформа из короткого списка не закрывает обязательную функцию даже живым расширением;
- эта функция не отменяется, если сузить задачу (например, публиковать научные данные в Dataverse, а оперативные — на портале);
- есть команда не только на запуск, но и на пять лет сопровождения;
- в своей системе всё равно будут постоянные адреса, лицензия на набор, выгрузка описаний и schema.org.

Если четвёртое «сделаем потом», своя разработка повторит самую частую беду самописных каталогов: сайтом пользуются люди, а программы его не видят. По выгрузке реестра от 9 октября 2026 года (выпуск 1.26.0 от 6 октября) среди каталогов показателей, где самописных больше всего, API есть лишь у 38%.
