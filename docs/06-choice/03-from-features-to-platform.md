# От функций к платформе

Короткий список из двух–четырёх платформ сравнивают по обязательным функциям. Платформа, у которой обязательная функция невозможна, выбывает до разговора о цене и о числе галочек.

Список функций к этому моменту уже есть: его собирают в главе [«Принципы выбора набора функций»](./02-feature-selection.md). Здесь его прикладывают к платформам.

## Шаг 1. Способ, потом марка

Сначала не CKAN и не Dataverse, а способ: чужой каталог, статический сайт, облачный сервис, свободное ПО, своя разработка. Критерии и цена ухода — в главе [«Свои силы, свободное ПО или облачный сервис»](./05-build-or-buy.md). Если данных мало и команды нет, сравнение CKAN с Dataverse не нужно: публикуйте в существующий каталог.

## Шаг 2. Короткий список

Две–четыре платформы того класса, который совпал с типом данных и способом. Ориентир — [классы ПО](../05-platforms/01-software-classes.md) и [карточки](../05-platforms/04-platform-profiles.md).

| Что публикуете | Обычный короткий список |
|----------------|-------------------------|
| Наборы органа власти, есть своя команда | CKAN, DKAN, udata |
| Наборы органа власти, команды нет | Huwise, Socrata, публикация в региональный или национальный портал |
| Научные данные с DOI | Dataverse, InvenioRDM, публикация в Zenodo |
| Слои и сервисы карт | GeoNetwork, ArcGIS Hub |
| Показатели | PxWeb, .Stat Suite, OpenSDG |
| Микроданные обследований | NADA, Dataverse |
| Десяток файлов без команды | статический сайт или Git-репозиторий |

Платформа из соседней строки в этот список не попадает. Научный репозиторий не закрывает ежедневный портал открытых данных, а CKAN с непроверенным расширением DOI не заменяет Dataverse.

## Шаг 3. Матрица

По каждой обязательной и желательной функции поставьте одну из четырёх пометок:

- **ядро** — есть в самой платформе;
- **расширение** — есть в названном модуле, и вы проверили, кто его сопровождает и с какой версией ядра он работает;
- **доработка** — в платформе есть куда это встроить, объём оценивает разработчик;
- **невозможно** — платформа так не умеет и не расширяется.

Платформа, у которой обязательная функция «невозможно», выбывает. Остальных сравнивают по цене запуска и сопровождения, а не по числу галочек.

«Доработка» и «невозможно» относятся только к этому сравнению. Сводка по платформам в [приложении](../12-appendices/03-platform-tables.md) пользуется другими словами: ядро, расширение, нет, не проверено. Клетку «нет» в матрицу переносят как «невозможно», только если дописать функцию нельзя. Клетку «не проверено» в матрицу не переносят: её закрывают по документации до того, как платформа попадёт в короткий список.

Пример для региона, которому нужны выгрузка DCAT для национального портала, сбор каталогов муниципалитетов и вход сотрудников через учётные записи организации. DOI региону не обязателен.

<div className="wide-table">

| Функция | CKAN | Huwise | Socrata | Свой сайт на генераторе |
|---------|------|--------|---------|-------------------------|
| Выгрузка DCAT | расширение ckanext-dcat, по умолчанию DCAT-AP 3 | ядро; национальный профиль бывает не у всех установок, его проверяют | ядро: файл `data.json` по DCAT-US, не DCAT-AP | доработка шаблона |
| API поиска | ядро | ядро | ядро | невозможно без отдельной программы |
| Свои поля под закон | расширение ckanext-scheming | ядро (шаблоны полей) | ядро (наборы полей) | доработка |
| Сбор каталогов муниципалитетов | расширение ckanext-harvest | ядро: сборщики CKAN, Socrata, ArcGIS, `data.json` и других порталов Huwise; CSW включают по запросу в поддержку | ядро: Catalog Connector забирает `data.json` и публичный ArcGIS Server | невозможно |
| Вход через учётные записи организации | расширение (SAML или OpenID Connect) | ядро: SAML и OpenID Connect | ядро: OpenID Connect; SAML через поддержку | нет |
| DOI | расширение; на CKAN 2.11 и 2.12 не тестировалось | нет | нет | нет |

</div>

Свои поля облачный сервис заводит в шаблонах без программиста, но в выгрузку DCAT они попадают, только если поставщик предусмотрел соответствие. У Socrata в файл `data.json` уходят поля с заранее известными именами.

Если национальный портал ждёт DCAT-AP, Socrata из этого списка выбывает: её штатный файл — DCAT-US. Huwise остаётся, пока на пилоте не видно нужного профиля. CKAN остаётся, если ckanext-dcat и расширение входа проверены на той версии ядра, которую собираются ставить. Если DOI вдруг обязателен, из этой четвёрки не остаётся никого: берут научный репозиторий, а не «CKAN плюс неизвестное расширение».

## Шаг 4. Проверка на живых данных

Поставьте пилот или откройте демонстрационный стенд и опубликуйте пять–десять настоящих наборов, включая неудобный: без лицензии в источнике, с большим файлом, с ежедневным обновлением. Затем проверьте так, как написано в главах о возможностях.

- Выгрузка DCAT открывается без входа и проходит валидатор того профиля, который ждёт верхний портал.
- На странице набора есть разметка schema.org, если набор должны находить поисковики.
- Адрес набора не меняется, когда поправили заголовок.
- Файл скачивается по прямой ссылке.
- Если в матрице стоит «расширение», на стенде стоит именно оно, и видна его версия.

Пилот на демонстрационных данных поставщика эту проверку не заменяет. У облачного сервиса в пилот входит и вопрос ухода: все описания и файлы выгружаются целиком.

## Когда оправдана своя разработка

Одновременно верны все четыре утверждения:

- ни одна платформа из короткого списка не закрывает обязательную функцию даже живым расширением;
- эта функция не отменяется, если сузить задачу (например, публиковать научные данные в Dataverse, а оперативные — на портале);
- есть команда не только на запуск, но и на пять лет сопровождения;
- в своей системе всё равно будут постоянные адреса, лицензия на набор, выгрузка описаний и schema.org.

Если четвёртое «сделаем потом», своя разработка повторит самую частую беду самописных каталогов: сайтом пользуются люди, а программы его не видят. По выгрузке реестра от 9 октября 2026 года (выпуск 1.26.0 от 6 октября) среди каталогов показателей, где самописных больше всего, API есть лишь у 38%.

## Шаг 5. Записать решение

Каждый развилочный выбор — платформа, расширение, отказ от функции, своя разработка — оформляют [карточкой решения](./04-justifying-decisions.md). Четыре полных примера такой цепочки — в главе [«Разобранные примеры»](./08-worked-examples.md).

## Типичные ошибки

- **Восемь платформ в одной таблице.** Короткий список длиннее четырёх сравнивать уже нечем: отличия тонут. Сначала отсекают класс, потом сравнивают марки.
- **Клетка «не проверено» переписана как «нет».** Так в прежней версии этой главы сбор у Huwise стоял непроверенным, хотя в документации сервиса сборщики есть. Незакрытую клетку закрывают по документации, а не вычёркивают платформу.
- **Расширение записано как недостаток.** ckanext-dcat — обычная часть взрослого портала на CKAN. Недостатком оно становится, когда на нужной версии ядра его не тестировали.
- **Пилот на данных поставщика.** Десять чужих демонстрационных наборов не показывают ваш большой файл, ваш профиль DCAT и ваш вход.
