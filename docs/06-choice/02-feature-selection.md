# Принципы выбора набора функций

[Маршрутная карта](./01-route-map.mdx) даёт первый ориентир за несколько минут. Эта глава — способ довести ориентир до списка функций, который можно положить в техническое задание.

Список функций берут не из рекламы платформы. Его собирают из задач. [Карта возможностей](../04-features/01-capability-map.md) подсказывает, какие функции вообще бывают и какие из них типичны для вашего типа каталога.

## Каждая функция отвечает на чью-то задачу

У функции должен быть источник. Их три:

- задача владельца: отчитаться по закону, выполнить условия гранта, продать сервис;
- задача того, кто данными пользуется: скачать таблицу, сослаться в статье, забрать описания программой;
- внешнее обязательство: национальный портал собирает DCAT, журнал требует DOI, инфраструктура INSPIRE требует каталог слоёв.

Функция без источника — кандидат на вычёркивание, даже если она есть «у всех». Витрина с анимацией на главной не помогает ни сборщику, ни автору статьи.

## Сначала то, без чего каталог невидим

Минимум одинаковый почти для всех:

- постоянный адрес набора;
- лицензия на набор, а не только на сайт;
- выгрузка всех описаний одним файлом;
- разметка schema.org на странице набора.

Поиск с фильтрами, предпросмотр и статистика идут после этого минимума. Красивый сайт без выгрузки описаний не попадает ни в национальный портал, ни в поисковик данных.

## Три уровня, и у каждого есть причина

Разложите функции так:

| Уровень | Смысл | Пример обоснования |
|---------|--------|--------------------|
| Обязательно | без этого задача не выполняется | «Национальный портал забирает DCAT-AP, иначе наши наборы не попадут в общую витрину» |
| Желательно | заметно помогает, но запуск возможен и так | «Предпросмотр таблицы уменьшит письма „что в файле“, но файл и так скачивается» |
| Не нужно | для этих задач лишнее | «DOI не нужен: данные оперативные, на конкретную версию не ссылаются» |

Отказ тоже записывают. Иначе через год его придётся объяснять заново.

## У функции есть цена

Функция в ядре платформы дешевле той же функции в расширении: расширение проверяют при каждом обновлении. Функция, которой нет ни в ядре, ни в живом расширении, — это своя разработка и годы сопровождения. Цену запуска и цену сопровождения оценивают отдельно: см. [скорость развёртывания](../04-features/09-deployment-and-operations.md).

## Не закрывайте себе следующий шаг

Спросите, что понадобится через три-пять лет: больше публикаторов, второй язык, сбор муниципальных каталогов, DOI для научных приложений. Отказ от функции сегодня допустим. Недопустим выбор платформы, с которой к этой функции потом нельзя подойти. Облачный сервис без своих расширений не обрастёт произвольной схемой полей. CKAN обрастёт, но ценой расширений.

## Что получается на выходе

Таблица, а не абзац «хотим современный портал»:

| Функция | Откуда потребность | Уровень | Почему так | Как проверим |
|---------|--------------------|---------|------------|--------------|
| Выгрузка DCAT-AP | национальный портал забирает описания | обязательно | иначе город не виден в стране | файл catalog.rdf проходит валидатор профиля |
| DOI | никто не ссылается на версию | не нужно | данные обновляются каждый квартал | — |

Дальше эта таблица превращается в выбор платформы: [следующая глава](./03-from-features-to-platform.md). Как хранить сам выбор — в главе [«Как обосновать решение»](./04-justifying-decisions.md).
