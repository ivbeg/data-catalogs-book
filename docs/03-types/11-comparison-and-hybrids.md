# Сравнение типов и гибриды

Типы каталогов различаются не названием, а главной единицей, стандартом описания и тем, без чего каталог не выполняет свою работу. Поэтому сравнивать каталог стоит с каталогами своего типа, а платформу выбирать под главный продукт.

Гибрид — сайт или организация, которые ведут каталоги нескольких типов сразу. Это частый случай: каталоги двух и более типов ведёт примерно каждое восьмое центральное ведомство и каждая восьмая международная организация. Но одной программой на все типы пользуются единицы. Практический вывод главы: назовите тип каждой части по тому, ради чего её открывают, выберите платформу под каждую часть и отдельно решите, как их связать — общей навигацией, общим поиском или сбором описаний в один каталог.

Цифры главы — по выгрузке реестра dataportals-registry от 9 октября 2026 года (выпуск 1.26.0 от 6 октября), в нём 43 415 каталогов. Запросы — в приложении [«Как работать с реестром»](../12-appendices/02-using-the-registry.md#сравнение-типов-и-гибриды). Живые сайты проверены 12 октября 2026 года.

«Ограниченный доступ» — доля каталогов, у которых хотя бы часть данных выдают по регистрации, заявке или за плату. «Не работают» — каталоги, которые не открываются или официально выведены из эксплуатации. Knoema в таблице — по записям реестра: сам сервис с января 2026 года не открывается, это разобрано в главе [о каталогах показателей](./05-indicator-catalogs.md#где-ломается).

Что видно из таблицы:

- **Своя разработка и API идут в разные стороны.** Где платформа общепринята — геопорталы, порталы открытых данных, микроданные, — API есть у двух третей каталогов и больше. Где каждый пишет своё — маркетплейсы, ML-каталоги, списки, — API у пятой части и меньше. Своя разработка редко доходит до программного интерфейса: его нужно не только написать, но и сопровождать.
- **Ограниченный доступ — признак типа, а не беды.** У маркетплейсов он почти всегда, у каталогов микроданных — у половины: в обследованиях сведения о людях. У портала открытых данных закрытый доступ — повод разбираться.
- **Доля мёртвых каталогов микроданных — след брошенных установок.** 47 из 59 неработающих — старые каталоги NADA статистических служб, которые ставили в рамках программ поддержки и перестали сопровождать. Разбор — в главе [о каталогах микроданных](./06-microdata-catalogs.md#где-ломается).
- **Специализированная платформа почти не выходит за свой тип.** CKAN — это 1 905 порталов открытых данных и всего 39 научных репозиториев. GeoNode (770), Dataverse (257) и PxWeb (107) встречаются каждый ровно в одном типе, NADA и DSpace — с одним исключением. Девять типов из одиннадцати собирает только WordPress, семь — Drupal, по шесть — Liferay и TYPO3: универсальная CMS о типе не говорит ничего.

## Чем типы отличаются по существу

Цифры показывают, как устроен рынок. Содержательная разница — в том, что каталог публикует и что он обязан сохранить.

| Тип | Главная единица | Стандарт описания | Без чего не работает | Что нельзя потерять | Кому отдаёт описания |
|-----|-----------------|-------------------|----------------------|---------------------|----------------------|
| Портал открытых данных | набор: файл или таблица | DCAT | выгрузка описаний в DCAT, открытая лицензия | адрес набора и лицензию | вышестоящему порталу, общим поисковикам |
| Геопортал | слой и картографический сервис | ISO 19115, CSW, OGC API Records | каталожный сервис и сами сервисы слоёв | возможность скачать, а не только увидеть | национальной инфраструктуре геоданных |
| Научный репозиторий | версия набора с DOI | DataCite | хранение файлов, DOI, версии, цитирование | версию, на которую сослались | DataCite, научным агрегаторам по OAI-PMH |
| Каталог показателей | показатель и временной ряд | SDMX | API рядов, методика и единицы измерения | методику ряда и его постоянный адрес | международным организациям по SDMX |
| Каталог микроданных | обследование и его файлы | DDI | уровни доступа, описание переменных | условия доступа и книгу кодов | архивам социальных данных |
| ML-каталог | набор для обучения и проверки моделей | Croissant, карточка набора | разбиение на части, лицензия, карточка | версию и разбиение, на которых меряли модель | площадкам и поисковикам по разметке |
| Маркетплейс | товар: набор или подписка | общего нет | договор, оплата, доставка | условия договора | никому: каталог закрыт для сбора |
| Поисковик или агрегатор | запись о чужом наборе | то, что собирает | сбор по протоколам, удаление дублей | ссылку на первоисточник | людям; иногда следующему агрегатору |
| Каталог метаданных | словарь, схема, описание каталога | SKOS, SDMX, ISO/IEC 11179 | постоянные адреса понятий, версии | старые версии понятий | системам, которые на него ссылаются |
| Каталог API | программный интерфейс | OpenAPI | описание интерфейса, условия доступа | историю версий интерфейса | порталу открытых данных, общим каталогам API |
| Список наборов | ссылка на файл | чаще никакого | живые ссылки | — | обычно никому |

Два вывода из таблицы. Первый: «без чего не работает» у соседних типов почти не пересекается. Портал без DCAT теряет федерацию, репозиторий без DOI — цитирование, каталог показателей без API рядов превращается в конструктор таблиц в браузере. Поэтому платформа, хорошая для одного типа, редко бывает хороша для соседнего. Второй: описания разных типов уходят в разные цепочки. Портал отдаёт DCAT национальному порталу, геопортал — ISO 19115 инфраструктуре геоданных, репозиторий — DataCite. Если сайт делает два дела, у него две цепочки, и обе нужно поддерживать. Какие возможности обязательны для какого сценария, подробно разобрано в главе [«Карта возможностей»](../04-features/01-capability-map.md).

## Гибриды

Гибридом в книге называют два разных случая. Первый — **один сайт**, на котором рядом живут два продукта: наборы и слои, наборы и описания API. Второй — **одна организация**, которая ведёт несколько каталогов разных типов: статистическая служба с показателями и микроданными, международная организация с порталом, геопорталом и библиотекой обследований. Самый развитый вариант второго случая — хаб данных: несколько каталогов под одной вывеской с общим поиском.

Гибрид — не новый тип. Каждую часть гибрида описывают и оценивают по её собственному типу: показатели статистической службы сравнивают с показателями других служб, а не с её же каталогом микроданных.

### Сколько организаций ведут каталоги разных типов

В реестре 32 452 владельца, если считать владельцем организацию с одним названием в одной стране. Каталоги двух и более типов у 2 176 из них, трёх и более — у 250. За этими владельцами 7 275 каталогов, то есть каждый шестой каталог реестра. Подсчёт по названию приблизительный: одно ведомство бывает записано по-разному, поэтому настоящих «многотипных» владельцев, скорее всего, больше.

Чем крупнее и централизованнее организация, тем чаще у неё несколько типов:

| Владелец | Доля владельцев с каталогами двух и более типов |
|----------|------:|
| Центральные органы власти | 12% |
| Международные организации | 12% |
| Региональные органы власти | 10% |
| Университеты и научные организации | 7% |
| Местные органы власти | 5% |
| Компании | 2% |

Пары типов повторяются. Среди владельцев ровно с двумя типами:

### Одна программа на два типа — редкость

Из 2 176 владельцев с несколькими типами всеми своими каталогами на одной программе обходятся 117, причём своя разработка здесь считается одной программой. Нагляднее всего пара «геопортал и портал открытых данных». Из 948 владельцев, у которых только эти два типа, одна и та же готовая платформа стоит на обеих сторонах у пятерых: у троих ArcGIS Hub, у одного Drupal, у одного WordPress. Ещё у 39 обе части — своя разработка. Остальные держат две разные программы: картографический сервер для слоёв и портальную платформу для наборов.

Это не небрежность, а следствие таблицы из предыдущего раздела. Геопорталу нужен каталожный сервис и сервисы слоёв, порталу — DCAT и скачивание файлов. Программ, которые одинаково хорошо делают и то и другое, мало, и владельцы выбирают по специализированной программе на каждую задачу.

## Пять видов гибридов

### Второй продукт как дополнение

Самый частый и самый простой случай. Основной продукт один, второй его дополняет.

- **Портал открытых данных с картой** остаётся порталом, если карта показывает уже опубликованные таблицы. Он становится геопорталом, если без сервисов WMS и WFS сайту нечего показать. В реестре у 43 порталов открытых данных отмечены слои карт как содержимое.
- **Геопортал с таблицами** остаётся геопорталом, если таблицы — атрибуты слоёв или пара файлов рядом с картой.
- **Научный репозиторий с картой** остаётся репозиторием, если карта — способ найти набор по месту наблюдения, а не продукт.

Правило: тип определяет то, что получает свой адрес и свою карточку. Карта, график или предпросмотр без своего адреса — функция, а не второй каталог. Такой гибрид решается одной платформой и одним расширением: например, CKAN с [ckanext-spatial](https://github.com/ckan/ckanext-spatial) для поиска по территории и [ckanext-geoview](https://github.com/ckan/ckanext-geoview) для предпросмотра слоёв. Если карты становятся главным продуктом, расширения уже не хватает: в главе [о CKAN](../05-platforms/03-ckan-and-extensions.md#три-рабочие-сборки) это разобрано как отдельная сборка с оговоркой, когда честнее взять геоплатформу.

### Одна платформа, несколько видов записей

Платформа изначально ведёт записи нескольких видов, и у каждого вида свой адрес и своя карточка. Это настоящий гибрид в одной программе.

- **[data.norge.no](https://data.norge.no/en)**, национальный каталог Норвегии, держит под одной вывеской пять каталогов: наборы, API, понятия, информационные модели, государственные услуги и события. На 12 октября 2026 года в нём 9 066 наборов, 1 071 API, 6 383 понятия и 1 393 услуги. Открытыми данными отмечены только 1 644 набора из 9 066. Остальные — описания данных, которые есть у государства, но не обязательно доступны всем: по сути, это каталог метаданных о государственных данных. Работает он на собственной разработке Felles datakatalog с [открытым кодом](https://github.com/Informasjonsforvaltning/fdk-portal) под лицензией Apache 2.0 и собирает описания из каталогов организаций в профиле DCAT-AP-NO. По типам это портал открытых данных, каталог API и каталог метаданных сразу. Реестр учитывает его дважды — порталом и каталогом API.
- **[data.gouv.fr](https://www.data.gouv.fr)** — 74 376 наборов, 1 265 сервисов данных (так здесь называют описания API) и 507 источников сбора. Бывший каталог API api.gouv.fr влит в портал, это разобрано в главе [о каталогах API](./10-other-types.md#каталоги-api). Сервисы данных и сбор описаний из CKAN и DCAT — в ядре его программы [udata](https://github.com/opendatateam/udata) (выпуск 17.12.1 от 9 октября 2026 года).
- **GeoNode** ведёт в ядре слои, карты, документы, истории на карте (GeoStories) и дашборды, а также собирает ресурсы с удалённых картографических сервисов — по [документации](https://docs.geonode.org/en/master/) выпуска 5.1.0 от 18 августа 2026 года. Это геопортал, внутри которого есть небольшой архив документов.
- **NADA** по [описанию проекта](https://nada.ihsn.org/) умеет описывать не только обследования, но и показатели, геоданные, документы и изображения — в DDI Codebook, Dublin Core, ISO 19115 и 19139, IPTC. Но возможность платформы ещё не делает каталог гибридом. В библиотеке микроданных Всемирного банка все 7 145 записей — обследования, других видов нет. Каталог остаётся каталогом микроданных, а показатели и геоданные банк публикует на других платформах.
- **ArcGIS Hub** — геопортал, который ведёт себя как портал открытых данных: каждый слой можно скачать файлом, каталог отдаётся в DCAT-US и DCAT-AP. Реестр записывает Hub геопорталом 3 464 раза и порталом открытых данных — 19. Подробнее — в главе [о геопорталах](./03-geoportals.md#каталог-открытых-геоданных-организации).

Такой гибрид работает, когда виды записей связаны между собой. В Норвегии набор ссылается на понятия, которыми описаны его поля, и на API, через который его получают. На data.gouv.fr сервис данных ссылается на набор, из которого он отдаёт строки. Если виды записей ничем не связаны, одна программа на них — просто экономия на сопровождении, и она оправдана только тогда, когда программа ведёт каждый вид не хуже специализированной.

### Портал, который ещё и собирает

Портал публикует свои наборы и одновременно собирает описания из чужих каталогов. data.gouv.fr принимает публикации напрямую и забирает описания из 507 источников. data.europa.eu собирает национальные порталы, а с 1 июля 2026 года на него ведёт и адрес закрытого геопортала INSPIRE. Для пользователя разницы нет: ищет он по всему сразу. Для владельца это два разных обязательства: за свои наборы он отвечает, а за собранные — только за то, чтобы не показывать мёртвое и не размножать дубли. Чем агрегатор отличается от поисковика и как устроен сбор, разобрано в главах [о поисковиках и агрегаторах](./09-search-engines-aggregators.md) и [о федерации и сборе](../07-publishing/03-federation-and-harvesting.md).

### Несколько каталогов одного владельца

Организация ведёт каталоги разных типов на разных программах, и связывает их только навигация на сайте. Так устроено большинство статистических служб. У мексиканского INEGI в реестре 22 записи четырёх типов: банк показателей и интерактивные таблицы, таблицы на PxWeb, служба SDMX, каталог микроданных на NADA (825 исследований на 12 октября 2026 года) и REDATAM для расчётов по переписям, картографический портал и страница открытых данных.

Это нормальная схема, если на сайте прямо сказано, что где лежит. «Показатель» и «файл обследования» — разные полки, и пользователю нужно объяснить, на какую идти. Почему для статистической службы два каталога лучше одного «универсального портала», разобрано в [примере статистической службы](../06-choice/08-worked-examples.md#статистическая-служба-показатели-и-микроданные--разные-каталоги).

### Хаб

Хаб — несколько каталогов разных типов под одной вывеской, связанные общей навигацией, а часто и общим поиском. Так устроены порталы международных организаций.

- **[Pacific Data Hub](https://pacificdata.org/)** Тихоокеанского сообщества по выгрузке реестра — больше 30 записей пяти типов: портал наборов на CKAN, микроданные на NADA, показатели на .Stat Suite со службой SDMX, геопорталы на GeoNode и картографическая витрина на TerriaJS, серверы THREDDS с океанографическими данными, каталог снимков STAC программы Digital Earth Pacific и демографические геопорталы PopGIS для пятнадцати стран.
- **Всемирный банк** держит отдельно [показатели](https://data.worldbank.org/), [библиотеку микроданных](https://microdata.worldbank.org/) и [каталог наборов](https://datacatalog.worldbank.org/), который собирает описания из остальных: на 12 октября 2026 года в нём 7 900 наборов, в том числе из библиотеки микроданных, финансовой и энергетической платформ. На главной data.worldbank.org сказано, что сайт открытых данных «расширяется до Data360», а адрес data360.worldbank.org ведёт туда же. В реестре за банком 27 записей пяти типов, большая часть — отдельные базы показателей.
- **ФАО** — каталог наборов на CKAN, больше десятка тематических карт на TerriaJS по адресам data.apps.fao.org, сайты на ArcGIS Hub и базы показателей на собственной платформе FENIX.

Хаб не делает каталоги одинаковыми. Он решает другую задачу: человеку, который пришёл за «данными о Фиджи», не нужно знать, что показатели лежат в .Stat Suite, а обследования — в NADA. Общий поиск хаба обычно строят сбором описаний из всех каталогов в один, как это делает каталог наборов Всемирного банка. Тогда у хаба появляется ещё одна цепочка сбора со всеми её проблемами.

## Как определить тип гибрида

Тип каждой части гибрида определяют те же вопросы, что и тип обычного каталога, — они разобраны в главе [о классификации](./01-classification.md#как-определить-тип). Для гибрида к ним добавляются четыре проверки.

1. **Что получает свой адрес.** Если у слоя, ряда или API есть своя карточка с постоянным адресом — это отдельная часть со своим типом. Если нет — это функция основного каталога.
2. **Что уходит в федерацию.** Посмотрите, что сайт отдаёт в DCAT, CSW или OAI-PMH. Если в выгрузке DCAT только наборы, а слои уходят по CSW в инфраструктуру геоданных, у сайта две цепочки и, по сути, два каталога.
3. **Какой поиск главный.** Если на главной один поиск по всему, а результаты ведут в разные программы, это хаб. Если поисков несколько и каждый ищет по своей полке, это несколько каталогов рядом.
4. **Какая программа за каждой частью.** Разные адреса на одном домене часто означают разные программы: `/catalog` — CKAN, `/microdata` — NADA, `/geoserver` — картографический сервер.

Классификацию гибрида записывают не одной строкой, а строкой на каждую часть, по шаблону из главы [о классификации](./01-classification.md#как-записать-классификацию-своего-каталога). Для INEGI это четыре строки: каталог показателей на своей разработке, PxWeb и службе SDMX; каталог микроданных на NADA с REDATAM; геопортал на своей разработке; портал открытых данных. Владелец, уровень и доступ у них общие, а тип, стандарт и платформа — разные.

## Как устроить гибрид: три схемы

Если вам нужно два типа сразу, выбор сводится к трём схемам.

| Схема | Когда подходит | Чем платите | Примеры |
|-------|----------------|-------------|---------|
| Одна платформа с расширениями | второй продукт маленький и его стандарт поддержан расширением или ядром | второй продукт сделан слабее, чем в специализированной программе; расширение нужно проверять при каждом обновлении | CKAN с ckanext-spatial, Dataverse для микроданных, GeoNode с документами |
| Две специализированные платформы и общая навигация | оба продукта важны, у каждого свой стандарт и своя цепочка | два сопровождения и два адреса; пользователю нужно объяснить, где что | статистическая служба: PxWeb или .Stat Suite и NADA; город: ArcGIS Server и CKAN |
| Хаб: несколько платформ и общий поиск | каталогов три и больше, и пользователю важно искать по всем сразу | ещё одна цепочка сбора, дубли, сопоставление идентификаторов, центральная команда | Pacific Data Hub, каталог наборов Всемирного банка, data.norge.no |

Что специализированные платформы умеют за пределами своего типа:

| Платформа | Свой тип | Второй продукт | Как |
|-----------|----------|----------------|-----|
| CKAN 2.12 | портал открытых данных | поиск по территории и сбор описаний геоданных по CSW | расширение [ckanext-spatial](https://github.com/ckan/ckanext-spatial) |
| CKAN 2.12 | портал открытых данных | предпросмотр слоёв WMS и GeoJSON | расширение [ckanext-geoview](https://github.com/ckan/ckanext-geoview), выпуск 0.3.2 от 2 октября 2026 года |
| CKAN 2.12 | портал открытых данных | сервисы слоёв, уровни доступа к микроданным, SDMX | нет: нужна вторая программа |
| ArcGIS Hub | геопортал | скачивание файлами и выгрузка в DCAT, как у портала открытых данных | ядро |
| GeoNode 5.1 | геопортал | документы, истории на карте, дашборды | ядро |
| Dataverse | научный репозиторий | микроданные: описание в DDI, файлы с ограниченным доступом | ядро |

Подробно возможности каждой платформы разобраны в [карточках платформ](../05-platforms/04-platform-profiles.md), а сводные таблицы — в [приложении](../12-appendices/03-platform-tables.md).

## Пример карточки решения: регион с картами и наборами

**Контекст.** Регион ведёт портал открытых данных на CKAN и отдаёт описания национальному порталу в DCAT-AP. Отдельно у регионального ведомства по земле работает картографический сервер со слоями и каталог GeoNetwork, который отдаёт описания по CSW в национальную инфраструктуру геоданных. Жители жалуются, что слои не находятся на портале, а руководство предлагает «свести всё в одно».

**Варианты.**

1. Перенести слои в CKAN файлами и закрыть геокаталог.
2. Заменить оба сайта одной геоплатформой, которая умеет и наборы, — например, ArcGIS Hub.
3. Оставить обе системы. CKAN с ckanext-spatial собирает описания слоёв из GeoNetwork по CSW и показывает их в общем поиске со ссылкой на сервисы. В национальный портал слои уходят только по одной цепочке.

**Критерии.** Не потерять обязательства перед инфраструктурой геоданных. Один поиск для жителя. Не породить дубли в национальном и европейском каталогах. Сколько программ сопровождать.

**Решение.** Вариант 3.

**Почему.** Вариант 1 ломает обязательство: инфраструктура геоданных ждёт описаний в ISO 19115 и сервисов слоёв, а не файлов. Вариант 2 возможен, но меняет обе системы сразу и привязывает регион к облаку одного поставщика; так делают трое из 948 владельцев этой пары в реестре. Большинство держит две программы — чаще всего картографический сервер и CKAN. Вариант 3 оставляет каждую программу на своём месте, а жителю даёт один поиск.

**Последствия.** На CKAN появляется ещё одно расширение, которое нужно проверять при обновлениях: ckanext-spatial на 2.12 проходит автоматические тесты, это записано в главе [о CKAN](../05-platforms/03-ckan-and-extensions.md). Собранные описания слоёв нужно исключить из выгрузки DCAT, если национальный портал сам собирает геокаталог, — иначе один слой дойдёт до data.europa.eu дважды. Как рвутся и путаются такие цепочки, разобрано в главе [о федерации](../07-publishing/03-federation-and-harvesting.md#где-цепочка-рвётся).

**Когда пересмотреть.** Если слои станут главным продуктом региона, а наборы — приложением к ним. Если национальный портал перестанет собирать геокаталоги напрямую. Если ckanext-spatial перестанут выпускать под новую версию CKAN.

## Где ломаются гибриды

**Дубли в федерации.** Один и тот же слой уходит наверх дважды: через геопортал по CSW и через портал открытых данных по DCAT. Агрегатор показывает две записи с разными адресами, и обе выглядят основными. Чтобы этого не было, у каждой части гибрида должна быть своя цепочка, а собранное из соседней части не отдают наверх повторно.

**Одна часть перевешивает всё.** Если обе части подключены к федерации, счёт определяет та, что режет данные мельче. На data.europa.eu из 850 тысяч немецких наборов 681 тысяча приходит из одного геокаталога, почти 450 тысяч из них — планы застройки отдельных участков. Сравнивая страны или организации, смотрите, из какой части гибрида пришли записи.

**Видна только одна часть.** Обратная беда: в федерацию подключили одну часть гибрида и забыли другую. В июне 2024 года data.europa.eu видел из Эстонии 324 набора, потому что собирал только национальный геопортал. После подключения портала открытых данных их стало 8,7 тысячи.

**Одна вещь — разные карточки.** Набор в портале и слой в геопортале описывают одни данные, но с разными названиями, лицензиями и датами обновления. Пользователь не понимает, какая карточка верная, а поисковик видит две.

**Два поиска без объяснения.** Сайт статистической службы с поиском по показателям и отдельным поиском по обследованиям, где ни один не говорит о существовании другого. Человек ищет обследование в поиске показателей, ничего не находит и уходит.

**Универсальная платформа делает второй продукт плохо.** CKAN, в который положили слои файлами, не даёт сервисов WMS и WFS. Каталог показателей на CMS отдаёт таблицы картинками и PDF. Возможность «умеет и это» в описании платформы не означает, что умеет так, как нужно второму типу.

**Хаб закрыт для программ.** Вся ценность хаба — в связях между каталогами, но некоторые хабы закрывают их от программ. 12 октября 2026 года API портала Pacific Data Hub, его GeoNode и каталог ФАО на CKAN отвечали программам проверкой Cloudflare, а таблицы INEGI на PxWeb — ошибкой 403. Человек в браузере данные видит, а агрегатор и исследователь со скриптом — нет. Как это отражается на находимости, разобрано в главе [о находимости](../07-publishing/05-discoverability.md).

**Одна часть хаба умирает, остальные живут.** Компоненты хаба стареют по-разному. У 110 владельцев, которые ведут и показатели, и микроданные, в реестре записаны 60 каталогов показателей на Knoema — сервисе, который с января 2026 года не открывается. Хаб нужно сопровождать как набор отдельных программ, у каждой из которых свой срок жизни.

**Тип по одной записи.** Агрегаторы и реестры записывают гибрид одним типом, и счёт типов от этого плывёт. ArcGIS Hub в реестре почти всегда геопортал, data.norge.no — портал открытых данных и каталог API одновременно. Сравнивая цифры по типам, помните, что граница между ними проведена человеком, а не программой.

## Как проверить гибрид

Посмотреть, что на самом деле лежит внутри, можно запросами к API. Все команды проверены 12 октября 2026 года.

```bash
# data.gouv.fr: наборы, сервисы данных (API) и источники сбора в одной программе
curl -s https://www.data.gouv.fr/api/1/site/ | jq '.metrics | {datasets, dataservices, harvesters}'

# data.norge.no: сколько записей в каждом из каталогов
for t in datasets data-services concepts services; do
  printf "%s: " "$t"
  curl -s -X POST -H 'Content-Type: application/json' \
    -d '{"pagination":{"size":1,"page":0}}' \
    "https://search.api.fellesdatakatalog.digdir.no/search/$t" | jq .page.totalElements
done

# NADA: какие виды записей реально есть в каталоге
for t in survey geospatial timeseries table document; do
  printf "%s: " "$t"
  curl -s "https://microdata.worldbank.org/index.php/api/catalog/search?ps=1&type=$t" | jq .result.found
done
```

Для библиотеки микроданных Всемирного банка последняя команда даёт 7 145 обследований и ноль записей остальных видов. Старые версии NADA параметр `type` не понимают и на любой вид отвечают одним и тем же числом — так отвечает каталог INEGI. Тогда виды записей смотрят в самом каталоге, в фильтре по типу данных.

Для CKAN полезно сравнить выгрузку DCAT с поиском: если в поиске есть слои, а в `/catalog.ttl` их нет, слои собраны из геокаталога и наверх уходят по другой цепочке. Команды для отдельных типов — в разделах «Как проверить» глав о каждом типе и в [чек-листах](../12-appendices/04-checklists.md).

## Правило

Назовите тип каждой части по тому, ради чего её открывают. Платформу выбирайте под эту часть, а не «максимально универсальную». Вторую задачу закройте расширением, если она маленькая, отдельной программой, если она важна, или честно урежьте. Связь между частями — навигация, общий поиск или сбор описаний — это отдельное решение со своей ценой, и его стоит записать в карточку решения, как в примере выше.
