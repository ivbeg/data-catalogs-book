# Экспорт цитирования

Люди ссылаются на данные, когда это занимает секунду. Если ссылку нужно собирать вручную из названия, года и адреса, большинство процитирует статью или не процитирует ничего.

Главный вывод главы: кнопка «Цитировать» стоит дёшево, дорого то, из чего она собирает ссылку. Генератор за миг соберёт строку из полей описания, но если в них нет автора, года и версии, получится аккуратно оформленная пустышка. Поэтому сначала проверяют поля и то, что набор, на который сослались, через год будет тем же самым. Кнопку делают потом. Если у набора есть DOI, ссылку в десятке форматов уже отдаёт DataCite, и задача каталога — не испортить её своей версией. Проверка в этой главе показывает, что это происходит: для одного и того же набора каталог и DataCite выдают разные ссылки.

## Что это

Экспорт цитирования — всё, что помогает сослаться на набор без ручной работы. У него четыре слоя, и платформы закрывают их по-разному.

**Строка на странице.** Блок «Как цитировать» с готовой ссылкой, которую копируют в текст статьи или отчёта.

**Файл для менеджера библиографии.** Менеджер библиографии — программа, где исследователь хранит свои источники и откуда вставляет ссылки в текст: Zotero, EndNote, Mendeley, JabRef. Ему отдают ссылку файлом в одном из форматов: BibTeX (для LaTeX), RIS и EndNote XML (для большинства менеджеров), CSL-JSON (для программ, которые оформляют ссылку по стилю CSL). Стиль CSL — описание правил оформления: APA, Chicago, ГОСТ, требования конкретного журнала.

**Подсказки для программ на самой странице.** Метатеги в заголовке HTML (`citation_title`, `citation_author` и другие, их придумал Google Scholar, или поля Dublin Core). По ним Zotero сохраняет набор одной кнопкой в браузере, а Google Scholar понимает, что перед ним. Сюда же относится заголовок ответа `Link` со ссылкой `rel="cite-as"`: он говорит программе, какой адрес считать адресом для ссылки. Это часть FAIR Signposting, коротко о нём — в [глоссарии](../12-appendices/01-glossary.md).

**Ссылка по идентификатору, без каталога.** Если у набора есть DOI, зарегистрированный в DataCite, его ссылку можно получить у самого DataCite, не заходя на сайт каталога. Этот приём называется согласованием содержимого (content negotiation): программа запрашивает адрес `https://doi.org/…` и в заголовке `Accept` просит не страницу, а, например, BibTeX. Команды — в разделе [о проверке](#как-проверить-живой-портал).

Две вещи часто путают с экспортом цитирования.

- Свойство `citation` в разметке schema.org — это не ссылка на сам набор, а статьи, которые автор просит процитировать вместе с ним. Google прямо пишет: для ссылки на набор используйте название, идентификатор, автора и издателя, а `citation` — для связанных статей.
- Требование лицензии CC BY указать автора — юридическое условие использования, а не научная ссылка. Принципы цитирования данных FORCE11 различают эти две вещи. Но готовая строка помогает выполнить и то и другое: GBIF, например, по соглашению с пользователем обязывает ссылаться на выгрузку по DOI, а каталог Ifremer пишет в условиях набора, что цитирование обязательно.

## Зачем нужна

**Чтобы автор данных получил признание.** Совместная декларация FORCE11 (2014) сформулировала восемь принципов цитирования данных. Первый — данные считаются полноценным результатом исследования, а ссылка на них весит столько же, сколько ссылка на статью. Для каталога важнее всего три других: уникальный идентификатор, долговечность ссылки и точность — ссылка должна указывать на ту версию или тот срез данных, на которых сделан вывод.

**Чтобы ссылку можно было посчитать.** Проект Make Data Count вместе с DataCite собирает корпус цитирований данных (Data Citation Corpus). В четвёртом выпуске от 27 июля 2025 года в нём 10,7 млн записей, из них 9,7 млн уникальных пар «набор — публикация». Почти половину записей, 5,2 млн, добавил Europe PMC — собрание статей по наукам о жизни. Его программы находят наборы не в списках литературы, а в тексте статей, где набор упомянут номером записи в базе, например в генетическом банке. Ещё часть корпуса дала такая же программная разметка статей от Chan Zuckerberg Initiative. Значит, на данные ссылаются чаще, чем видно по спискам литературы, но считать такие ссылки трудно и неточно. Аккуратная ссылка с DOI в списке литературы — то, что попадает в учёт без догадок.

Насколько учтённых ссылок мало, видно по самому DataCite. 12 октября 2026 года из его API взяты три тысячи случайных DOI с типом «набор данных». Больше половины из них (1667) выпустил японский Национальный институт термоядерного синтеза (NIFS), поэтому считать лучше без него. Из оставшихся 1333 DOI хотя бы одно цитирование, известное DataCite, есть у 78 — около 6%.

**Чтобы владелец каталога видел пользу.** Ссылки в статьях и отчётах — самый убедительный довод для руководства и грантодателя, что каталог нужен. Счётчик скачиваний говорит, что файл забрали, ссылка — что из него что-то сделали.

**Чтобы пользователь не ошибся.** Без готовой строки каждый собирает ссылку сам: кто-то пишет название портала вместо издателя, кто-то — дату скачивания вместо года публикации, почти никто не пишет версию. По такой ссылке набор не найти, а если найти, то не тот.

## Из чего состоит ссылка

DataCite рекомендует такой порядок элементов:

```text
Автор (Год). Название. Версия. Издатель. Тип ресурса. Идентификатор
```

Минимальная ссылка — без версии и типа: автор, год, название, издатель, идентификатор. Так выглядит ссылка на реальный набор Harvard Dataverse в стиле APA:

```text
Durbin, P. (2017). Open Source at Harvard (Version 5.0) [Dataset]. Harvard Dataverse. https://doi.org/10.7910/DVN/TJCLKP
```

Каждый элемент ломается по-своему.

**Автор.** Люди или организация. Для государственных данных автор-организация — норма: «Росстат (2026)» лучше, чем фамилия сотрудника, который выгрузил файл. Ошибка — смешать роли: поставить в авторы отдел, который ведёт каталог, или издателя рядом с людьми.

**Год.** Год публикации набора или его версии, а не год, когда пользователь его скачал, и не год создания карточки. Если программа берёт год из даты заведения записи, после переноса наборов на новый портал у всех них станет год переноса.

**Название.** Название набора, а не имя файла и не название портала.

**Версия.** Без неё ссылка ведёт на набор вообще, а не на то, что использовали. В той же выборке DataCite версия заполнена только у 191 DOI из 1333 — у 14%. Но и заполненная версия не всегда доходит до ссылки: BibTeX, который DataCite отдаёт для набора Harvard Dataverse, версии не содержит, хотя у набора пять версий, а ссылка APA от того же DataCite её содержит.

**Издатель.** Организация, которая опубликовала набор: репозиторий, ведомство, институт.

**Тип ресурса.** Пометка «[Dataset]» отличает ссылку на данные от ссылки на статью. В классическом BibTeX типа для данных нет, и каждый выкручивается сам: DataCite отдаёт `@misc`, Dataverse — нестандартный `@data`, InvenioRDM — `@dataset`, который понимает biblatex, современная замена BibTeX.

**Идентификатор.** DOI в виде адреса `https://doi.org/…`. Если DOI нет, ставят постоянный адрес страницы набора и дату обращения. Российский ГОСТ Р 7.0.108-2022 о ссылках на сетевые документы так и требует: адрес и дата обращения обязательны, а DOI в стандарте не упоминается вовсе. Базы данных в нём названы одним из видов электронных документов.

Если поля описания пусты, генератор ссылки не поможет. Какие поля нужны и как проверить, что они заполнены по существу, разобрано в главе [о полноте метаданных](./03-metadata-depth.md); как устроены DOI и версии — в главе [об идентификаторах](./06-identifiers-and-doi.md).

### Ссылка на меняющиеся данные

Научный репозиторий фиксирует версию, и ссылка на неё остаётся точной. Портал открытых данных и каталог показателей чаще ведут один набор, файлы которого заменяют каждую неделю. Ссылка «Минтранс (2026). Расписание пригородных поездов» через месяц указывает уже на другие данные. Способов справиться с этим пять, от простого к сложному.

1. **Дата обращения и архив выгрузок.** Ссылка содержит дату, а портал хранит прошлые файлы, так что состояние на эту дату можно восстановить. Без архива дата обращения только честно признаёт, что проверить ссылку нельзя.
2. **Снимок страницы.** Our World in Data предлагает ссылаться не на живую страницу графика, а на её архивный снимок с датой в адресе (`archive.ourworldindata.org/20260910-…`). Там же он просит сослаться и на первоисточник, и на себя как на обработчика: «Gapminder (2015); UN IGME (2025) – processed by Our World in Data». Двухуровневая ссылка нужна любому агрегатору и любому порталу, который перепубликует чужие данные.
3. **Версии с собственным идентификатором.** Каждая выгрузка набора становится версией. Так делают Zenodo и Figshare, так можно делать и на портале, если выпусков немного.
4. **Ссылка на запрос.** GBIF выдаёт свой DOI каждой выгрузке наблюдений: в ней записаны условия отбора, список наборов-источников и дата. Если пользователь потом сильно отфильтровал выгрузку или собрал данные через API, он регистрирует «производный набор» (derived dataset) и тоже получает DOI. Общая схема описана в рекомендациях Research Data Alliance о ссылках на меняющиеся данные: данные хранят с версиями и метками времени, сохраняют сам запрос с меткой времени и выдают ему идентификатор, по которому запрос можно выполнить снова на том же состоянии данных. Новая редакция рекомендаций одобрена в июле 2025 года: в ней 12 пунктов вместо 14 в редакции 2015 года, суть не изменилась.
5. **Ссылка на часть набора.** Dataverse показывает отдельную ссылку для каждого файла набора, GBIF — для отдельного наблюдения. Это нужно, когда вывод опирается на один файл из ста.

Для портала открытых данных разумный минимум — первый способ: дата обращения в предлагаемой строке и архив прошлых выгрузок. Как хранить прошлые файлы, разобрано в главе [о хранилище данных](./05-data-storage.md).

## Варианты реализации

**Шаблон строки на странице.** Самый дешёвый способ: в шаблон страницы набора вставляют строку, собранную из полей. Так работает расширение ckanext-doi для CKAN: блок «Cite this as» собирается из автора, года, названия и издателя, к нему добавляется ссылка на DOI. Цена — одна правка темы оформления. Риск — один стиль на всех и ошибки в выборе полей: тот же ckanext-doi берёт год из даты создания записи в CKAN.

**Генератор со стилями CSL.** Платформа хранит стили CSL и по запросу оформляет ссылку в нужном стиле и формате. Стилей много: в репозитории CSL в октябре 2026 года 2863 самостоятельных стиля и ещё 8002 «зависимых» — для журналов, которые используют чужой стиль под своим именем. Так устроены Dataverse, InvenioRDM и Zenodo, GeoNetwork, расширение ckanext-citeproc для CKAN. Цена — сопровождение набора стилей и соответствия полей переменным CSL.

**Ссылка от DataCite.** Каталог ничего не генерирует сам, а берёт ссылку у DataCite по DOI. Так делает NADA, а кнопка BibTeX в ckanext-doi ведёт прямо в API DataCite. Плюс — ссылка совпадает с той, что получит любой другой сервис. Минусы — работает только для наборов с DOI, DataCite ничего не знает о версиях, которые не записаны в его метаданных, и у его генератора есть ловушки:

- неизвестное имя стиля DataCite молча заменяет на APA. Запрос стиля `gost-r-7-0-100-2018` возвращает обычную ссылку APA без всякого предупреждения. InvenioRDM на такой же запрос честно отвечает ошибкой;
- стилей по ГОСТ в репозитории CSL три, все по старому ГОСТ Р 7.0.5-2008, и ни один не выводит для набора данных DOI. Для набора Harvard Dataverse они дают «Durbin P. Open Source at Harvard // 2017.» и «Durbin P. Open Source at Harvard. Harvard Dataverse, 2017.» Если каталогу нужна ссылка по ГОСТ, шаблон для данных лучше написать самому.

**Метатеги для менеджеров библиографии.** Метатеги `citation_*` и Dublin Core в заголовке страницы стоят почти ничего и дают сохранение одной кнопкой в Zotero и правильную карточку в Google Scholar. В ядре DSpace они есть даже там, где нет никакого блока ссылки. У Zotero есть и отдельные программы-трансляторы для крупных платформ — Dataverse, InvenioRDM, Figshare, Dryad, DSpace. Но транслятор привязан к списку адресов: транслятор InvenioRDM знает 14 сайтов, от zenodo.org до репозитория Тюбингенского университета. Новую установку он не узнает, и Zotero останется только читать метатеги. У метатегов есть предел: в словаре Google Scholar нет ни версии, ни типа «набор данных», поэтому Zotero по ним часто сохраняет набор как веб-страницу или статью. Тип умеет передать старый формат COinS, но его почти никто не ставит. Тип «Dataset» в самом Zotero есть с версии 6.0.24.

**Файл в репозитории.** Для данных на GitHub роль кнопки играет файл `CITATION.cff` в корне репозитория. GitHub показывает по нему ссылку «Cite this repository» в двух форматах — APA и BibTeX. Чтобы ссылка была на данные, а не на программу, в файле нужна строка `type: dataset`. Без неё GitHub оформит набор как программу: «[Computer software]» в APA и `@software` в BibTeX.

| Вариант | Что получает пользователь | Цена | Главный риск |
|---------|---------------------------|------|--------------|
| Шаблон строки | одну строку в одном стиле | правка темы | неверно выбранные поля, особенно год |
| Генератор CSL | строку в любом стиле и файлы для менеджеров | платформа или расширение, набор стилей | плохое соответствие полей переменным CSL |
| Ссылка от DataCite | строку и файлы, совпадающие с другими сервисами | ничего, если DOI уже есть | нет DOI — нет ссылки; молчаливая замена стиля |
| Метатеги | сохранение одной кнопкой в Zotero | несколько строк в шаблоне | нет версии и типа «набор данных» |
| `CITATION.cff` | кнопку на GitHub, метаданные для Zenodo | один файл | без `type: dataset` получится ссылка на программу |

Варианты не исключают друг друга. Хороший научный репозиторий делает все сразу: строку, файлы, метатеги и DOI, по которому DataCite отдаёт ту же ссылку.

## Когда нужна, а когда нет

| Ситуация | Что нужно | Чем обычно закрывают |
|----------|-----------|----------------------|
| Научный репозиторий | строка с версией и DOI, BibTeX и RIS, метатеги, ссылка на файл набора | ядро Dataverse, InvenioRDM, Figshare |
| Портал открытых данных при университете или министерстве, где данными пользуются исследователи | строка с постоянным адресом и датой обращения, архив прошлых выгрузок | правка шаблона; для наборов, на которые ссылаются в статьях, — копия в научном репозитории с DOI |
| Каталог показателей и статистики | ссылка на ряд или запрос с датой, а не на страницу таблицы | ссылка на сохранённый запрос, как у GBIF; снимок, как у Our World in Data |
| Геопортал с наборами, на которые ссылаются учёные | строка из полей ISO 19115 и DOI | ядро GeoNetwork 4.4 |
| Хаб для машинного обучения | DOI на ревизию набора и строка в карточке | DOI по запросу на Hugging Face; ссылка от DataCite |
| Публикация в Git-репозитории | `CITATION.cff` с `type: dataset`, DOI выпуска | GitHub и Zenodo |
| Служебная витрина, слой внутренней карты | постоянный адрес | генератор ссылок не нужен |

Обязательно это научному репозиторию: цитирование — часть его задачи, а журналы и грантодатели требуют ссылку на данные. Желательно везде, где данными пользуются в исследованиях и аналитике. Не нужно, если на данные не ссылаются: оперативная витрина, внутренний слой карты. Даже там постоянный адрес полезен, а генератор BibTeX — нет.

Коротко, как выглядит обоснование по шаблону [карточки решения](../06-choice/04-justifying-decisions.md):

- **Контекст.** Портал открытых данных университета на CKAN 2.11. Исследователи просят «кнопку цитирования». DOI у портала нет, договора с DataCite тоже.
- **Варианты.** Строка в шаблоне страницы набора; расширение ckanext-citeproc со стилями CSL; ckanext-doi с договором и префиксом DataCite; отправлять наборы, на которые ссылаются в статьях, в Dataverse или Zenodo.
- **Критерии.** Точность ссылки (версия, постоянный адрес), стоимость обновлений CKAN, нужен ли DOI.
- **Решение.** Строка в шаблоне с постоянным адресом и датой обращения, архив прошлых выгрузок. Наборы к статьям — в научный репозиторий с DOI.
- **Почему.** Десять стилей CSL не делают ссылку без версии и DOI точнее. Строка в шаблоне не зависит от чужого расширения, а ckanext-doi требует договора, ради которого портал не создавался.
- **Когда пересмотреть.** Если университет получит префикс DOI через библиотечный консорциум или если ckanext-citeproc выпустит стабильную версию с проверкой на CKAN 2.12.

### Расширения и их риски

У CKAN в ядре цитирования нет. Кандидатов три, и у каждого своя оговорка. Методика оценки расширения — в главе [об экосистемах расширений](../05-platforms/02-extension-ecosystems.md).

- **ckanext-doi** Музея естественной истории в Лондоне. Выдаёт DOI через DataCite и показывает блок «Cite this as» с кнопкой BibTeX, которую отдаёт DataCite. Без DOI цитирования нет. Документация называет CKAN 2.9 и 2.10, на 2.11 и 2.12 расширение не тестировалось; подробнее — в главе [про CKAN](../05-platforms/03-ckan-and-extensions.md).
- **ckanext-citeproc** выложила команда портала open.canada.ca в марте 2025 года, лицензия MIT. Оформляет ссылку на набор и на ресурс по стилям CSL, которые администратор кладёт в папку на сервере: в комплекте библиотеки только один стиль, Harvard. Совместимость заявлена с CKAN 2.10 и 2.11, автоматические тесты идут на основной ветке CKAN. На самом open.canada.ca (CKAN 2.10.8) в октябре 2026 года расширение не включено.
- **ckanext-citation** группы TIB в Ганновере появилось в июне 2026 года, лицензия AGPL-3.0. Отдаёт BibTeX, RIS, EndNote, APA, формат ACM и CSL-JSON. Заявлены CKAN 2.9 и 2.10. Тесты проверяют только оформление ссылки, на живом CKAN расширение автоматически не проверяется. Под тем же именем есть старое расширение тайваньского репозитория depositar: оно не обновлялось с 2022 года и знает только название, автора и адрес.

Для DSpace 6 существовали сторонние дополнения — модуль CSL компании Atmire и выгрузка в RIS Университета Уаикато. В DSpace 7 и новее они не перенесены. В GeoNetwork состав строки правят в файле XSL внутри схемы ядра: такую правку придётся повторять после каждого обновления.

## Как ломается: один набор — три ссылки

Проверка 12 октября 2026 года: для каждого набора сравнивалась ссылка, которую выдаёт сам каталог, и ссылка, которую по тому же DOI отдаёт DataCite.

**Harvard Dataverse (Dataverse 6.10.1), набор «Open Source at Harvard».** У набора пять версий: первая — июль 2017 года, пятая — июнь 2026 года.

- Строка на странице: `Durbin, Philip, 2017, "Open Source at Harvard", https://doi.org/10.7910/DVN/TJCLKP, Harvard Dataverse, V5, UNF:6:…` — с версией и контрольной суммой.
- BibTeX от самого Dataverse для первой версии: `version = {V1}`, тип `@data`.
- BibTeX от DataCite: версии нет, тип `@misc`.
- APA от DataCite: «(Version 5.0)».

Пользователь, взявший BibTeX у DataCite, сошлётся на набор без версии, то есть фактически на последнюю. Через год это будут уже другие данные.

**Каталог Ifremer Sextant (GeoNetwork 4.4.13), климатология температуры и солёности Средиземного моря.**

- Строка от каталога: `IFREMER / IDM/SISMER, Simona Simoncelli, Paolo Oliveri . SeaDataCloud Mediterranean Sea - Temperature and Salinity Climatology V1. https://doi.org/10.12770/…` — года нет, организация стоит первым автором.
- BibTeX от каталога: `author = {IFREMER / IDM/SISMER, Simona Simoncelli, Paolo Oliveri}`, `publisher = {}`. BibTeX разделяет авторов словом `and`, а не запятыми, поэтому менеджер библиографии прочитает трёх авторов как одного с длинным именем. Издатель пуст.
- APA от DataCite: `Simoncelli, S., & Oliveri, P. (2019). … (Version 1.1) [Dataset]. IFREMER / IDM/SISMER.` — с годом, версией и издателем.

Поля в описании есть, но генератор каталога берёт их не из тех ролей. Это типичная поломка: функция «в ядре», а результат хуже, чем у внешнего сервиса.

**InvenioRDM (демонстрационный стенд) и стиль ГОСТ.** BibTeX и APA собраны верно: автор, год, версия, издатель, DOI. Стиль `gost-r-7-0-5-2008` даёт «Gallagher J. и др. Jones and Sons's gallery // 1987–2018.» — без издателя и без DOI. Дело не в платформе, а в стиле CSL: для набора данных он не написан.

Ещё четыре поломки встречаются часто:

- **Нет версии.** Ссылка верна по форме и бесполезна для проверки. В выборке DataCite версия заполнена у 14% наборов.
- **Год из даты карточки.** Программа подставляет год создания записи, а не публикации данных. После переноса на новую платформу все наборы «публикуются» в год переноса.
- **Молчаливая подмена стиля.** DataCite на неизвестный стиль отдаёт APA, и пользователь уверен, что получил то, что просил.
- **Ссылка на программу вместо данных.** `CITATION.cff` без `type: dataset` на GitHub даёт «[Computer software]».

## Публикация без портала

Без портала ссылку целиком собирает автор, зато и ошибиться в ролях некому, кроме него. Хватает трёх вещей.

**`CITATION.cff` в корне репозитория.** Версия формата — 1.2.0, она не менялась с 2021 года. Обязательны `cff-version`, `message`, `title` и `authors`; для данных добавляют `type: dataset`, версию, дату выпуска и DOI, когда он появится. GitHub покажет по файлу кнопку «Cite this repository». Zenodo при архивации выпуска возьмёт из него авторов и название, но только если в репозитории нет файла `.zenodo.json`: если он есть, `CITATION.cff` Zenodo игнорирует. Тип записи Zenodo — набор данных, а не программа — задают полем `upload_type` в `.zenodo.json`. Как совместить оба файла, разобрано в главе [о Git-репозиториях](../08-beyond-portals/03-git-repositories.md#выпуск-и-doi). Проверить файл можно программой `cffconvert --validate`. Готовый [шаблон CITATION.cff](pathname:///templates/CITATION.cff) лежит в шаблонах книги.

**Строка «Как цитировать» в README и на странице набора.** Одна строка в стиле, принятом в вашей области, с версией и постоянным адресом, а после архивации в Zenodo — с DOI. У Zenodo две ссылки на выбор: DOI конкретного выпуска и общий DOI всех версий, который всегда ведёт на последнюю. Для статьи нужен первый.

**Разметка на странице набора.** Разметка schema.org с автором (`creator`), датой публикации (`datePublished`), версией (`version`) и издателем (`publisher`) — её читают Google и агрегаторы. Поле `identifier` добавляют, когда DOI уже выдан: в [шаблоне](pathname:///templates/schema-dataset.jsonld) его нет, чтобы не опубликовать пустой номер. Для Zotero полезны ещё несколько метатегов:

```html
<meta name="citation_title" content="Название набора данных">
<meta name="citation_author" content="Фамилия, Имя">
<meta name="citation_date" content="2026/01/15">
<meta name="citation_publisher" content="Организация-издатель">
```

Когда DOI выдан, к этим полям добавляют `citation_doi` с настоящим номером. Версию в метатеги не передать, поэтому она должна быть в названии или в строке «Как цитировать». Как устроить сам репозиторий и выпуски, разобрано в главе [о Git-репозиториях](../08-beyond-portals/03-git-repositories.md).

## Как проверить живой портал

Ручная проверка — пять вопросов к пяти случайным наборам:

1. На странице набора есть блок «Как цитировать» с автором, годом, названием, издателем и идентификатором.
2. Год в ссылке — год публикации набора или версии, а не год создания карточки и не сегодняшний.
3. Для двух версий одного набора ссылки различаются номером версии или идентификатором. Если версий нет, в ссылке есть дата обращения.
4. Скачивается BibTeX или RIS, в нём тот же идентификатор и та же версия, что на странице, а авторы разделены как положено (в BibTeX — словом `and`).
5. Если у набора есть DOI, ссылка от DataCite совпадает со ссылкой на странице по автору, году и версии.

### Команды

Ссылка по DOI от DataCite — в стиле, в BibTeX и в RIS. Работает для любого DOI, выпущенного через DataCite, даже если у каталога нет никакой кнопки:

```bash
DOI=10.7910/DVN/TJCLKP
curl -sLH "Accept: text/x-bibliography; style=apa" "https://doi.org/$DOI"; echo
curl -sLH "Accept: application/x-bibtex" "https://doi.org/$DOI"; echo
curl -sLH "Accept: application/x-research-info-systems" "https://doi.org/$DOI"
```

Если стиль написан с ошибкой, ответ всё равно придёт — в стиле APA. Проверяйте, что получили то, что просили. Список имён стилей — в [репозитории CSL](https://github.com/citation-style-language/styles).

Dataverse: ссылка для конкретной версии в BibTeX, RIS, EndNote или CSL-JSON:

```bash
SERVER=https://dataverse.harvard.edu
PID=doi:10.7910/DVN/TJCLKP
curl -s "$SERVER/api/datasets/:persistentId/versions/1.0/citation/BibTeX?persistentId=$PID"
curl -s "$SERVER/api/datasets/:persistentId/versions/:latest-published/citation?persistentId=$PID"
```

InvenioRDM: строка в выбранном стиле и BibTeX. Пример — CaltechDATA; сам Zenodo программам без браузера в октябре 2026 года не отвечал:

```bash
SERVER=https://data.caltech.edu
ID=$(curl -s "$SERVER/api/records?size=1&q=metadata.resource_type.id:dataset" | jq -r '.hits.hits[0].id')
curl -s -H "Accept: text/x-bibliography" "$SERVER/api/records/$ID?style=apa&locale=en-US"; echo
curl -s -H "Accept: application/x-bibtex" "$SERVER/api/records/$ID"
```

GeoNetwork 4.4: список форматов и ссылка в RIS для записи:

```bash
API=https://sextant.ifremer.fr/geonetwork/srv/api
UUID=ad07a55f-5de7-4abc-ba89-8899b16c4b59
curl -s "$API/records/$UUID/formatters/citation?format=?"; echo
curl -s "$API/records/$UUID/formatters/citation?format=ris"
```

Подсказки для программ на странице — метатеги и заголовок `cite-as`:

```bash
PAGE=https://dspace.mit.edu/handle/1721.1/93094
curl -sL "$PAGE" | grep -o -E '<meta name="(citation_|DC\.)[a-zA-Z_.]*"' | sort | uniq -c
curl -sI https://data.caltech.edu/records/$ID | grep -i '^link' | tr ',' '\n' | grep cite-as
```

Пустой вывод первой команды значит, что Zotero сохранит набор как обычную веб-страницу. Пустой вывод второй — что программа не узнает, какой адрес считать адресом для ссылки.

## Что из этого следует

- Сначала поля, потом кнопка: автор, год публикации, название, версия, издатель, идентификатор. Без них любой генератор выдаёт пустышку.
- Если у наборов есть DOI, сверьте свою ссылку со ссылкой DataCite. Расхождение по автору, году или версии — ошибка, которую исправляют в описании, а не в шаблоне.
- Для меняющихся данных добавьте в ссылку дату обращения и храните прошлые выгрузки. Для научных ссылок — фиксируйте версии или выдавайте идентификатор выгрузке, как GBIF.
- Метатеги `citation_*` и Dublin Core стоят несколько строк шаблона и экономят пользователю ручной ввод.
- Ссылку по ГОСТ для набора данных стили CSL не соберут правильно: напишите шаблон сами.
- В Git-репозитории с данными нужен `CITATION.cff` со строкой `type: dataset`.
