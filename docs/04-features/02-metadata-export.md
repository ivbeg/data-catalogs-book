# Экспорт метаданных

Каталог полезен не только людям на его сайте. Другие порталы, поисковики и программы должны уметь прочитать описания наборов. Для этого каталог отдаёт метаданные в формате, который эти системы уже понимают.

Главный вывод главы: ответить по адресу `/data.json` — ещё не значит отдать описания. У выгрузки есть профиль, и профили не взаимозаменяемы: data.europa.eu ждёт DCAT-AP, data.gov — DCAT-US, Google — разметку на странице набора. Платформа обычно умеет несколько форматов сразу, но нужный профиль включают настройкой, а поля описания должны быть заполнены так, как требует именно он. Сами стандарты разобраны в главе [«Стандарты метаданных»](../07-publishing/02-metadata-standards.md). Здесь — о возможности платформы их отдавать.

## Что это

Экспорт метаданных — это готовое описание набора или всего каталога в формате, который читает чужая система. У него три адресата, и под каждого свой формат.

**Другие каталоги.** Им нужен общий словарь описаний. Для открытых данных это DCAT — рекомендация W3C, словарь каталогов данных. По нему национальный портал забирает региональные, а общий европейский портал — национальные. Сам DCAT задаёт только смысл полей. Что из них обязательно и какими словами их называть, решает профиль — уточнение словаря под страну или отрасль:

- **DCAT-AP** — профиль для Европы. Действующая версия — 3.0.1, рекомендация SEMIC от 27 октября 2025 года. Черновик 3.0.2 от 17 июня 2026 года рекомендацией ещё не стал. Поверх него есть отраслевые уточнения: GeoDCAT-AP для геоданных, StatDCAT-AP для статистики, DCAT-AP HVD для наборов высокой ценности, HealthDCAT-AP для медицинских данных;
- **DCAT-US** — профиль для федеральных ведомств США. Ведомство публикует один файл `data.json`, а data.gov его собирает. Новая версия — DCAT-US 3.0, она построена на DCAT 3. Старую версию 1.1 data.gov ещё принимает на переходный период.

**Поисковики.** Им нужна разметка прямо в HTML-странице набора: блок `application/ld+json` со словарём schema.org и типом Dataset. Её читает Google Dataset Search. Это не замена DCAT: у разметки другая аудитория, и Google прямо пишет, что понимает и schema.org, и DCAT, но разметку ищет на странице набора.

**Отраслевые системы.** У них свои форматы и протоколы:

- геоданные — ISO 19115 и каталожный сервис CSW, а также OGC API Records;
- наука — схема DataCite и протокол OAI-PMH;
- микроданные — DDI;
- статистика — SDMX;
- машинное обучение — Croissant поверх schema.org.

Протокол и формат — разные вещи, и их часто смешивают. CSW и OAI-PMH отвечают на вопрос «как спросить каталог». DCAT, ISO 19115 и DataCite отвечают на вопрос «на каком языке придёт ответ». Один и тот же CSW умеет ответить и карточкой ISO 19115, и описанием DCAT — если это умеет программа каталога.

## Зачем нужна

Без стандартной выгрузки каталог виден только тем, кто открыл его сайт. Вот кто остаётся за бортом.

**Вышестоящий портал.** Он собирает описания по профилю, который принят в стране, и по известным адресам. Каталог с «почти DCAT» или со своим JSON в сбор не попадёт, даже если набор полей похож. Как устроены такие цепочки и где они рвутся — в главе [о федерациях и сборе](../07-publishing/03-federation-and-harvesting.md).

**Поисковик по данным.** В ноябре 2024 года Google Dataset Search по русским запросам выдавал на первых местах наборы с hubofdata.ru и ngodata.ru — двух небольших общественных порталов на CKAN. Не потому, что они самые полные, а потому, что на их страницах есть разметка schema.org. Портал открытых данных Москвы data.mos.ru, крупный и рабочий, не отдавал ни schema.org, ни DCAT, и его наборов не было ни в Google Dataset Search, ни в поисковике Dateno. Так же в 2022 году выпадал портал Индии data.gov.in: обычный поиск Google его индексировал, поиск по данным — нет. Разметка важнее размера каталога.

**Агрегаторы и архивы.** Им нужна полная выгрузка, которую можно повторить: один файл или протокол с выборкой по дате. Карта сайта для этого не годится — в ней только адреса страниц, без лицензии и файлов. Чем выгрузка описаний отличается от API поиска, разобрано в главе [об API и массовой выгрузке](./04-access-interfaces.md).

**Закон.** Для органов власти в ЕС профиль DCAT-AP — практическое требование обмена с data.europa.eu. Для наборов высокой ценности по регламенту 2023/138 к нему добавляется профиль DCAT-AP HVD.

Выгрузка не исправляет пустые поля. Если в описании нет лицензии и издателя, в DCAT их тоже не будет: программа переносит то, что заполнено. Какие поля требуют профили и как проверить, что они заполнены по существу, разобрано в главе [о полноте метаданных](./03-metadata-depth.md).

## Варианты реализации

Описания отдают пятью способами. Они не исключают друг друга: взрослому каталогу нужны сразу несколько.

| Способ | Что получает потребитель | Сильная сторона | Слабое место |
|--------|--------------------------|-----------------|--------------|
| Разметка на странице | schema.org в HTML каждого набора | её читает поисковик, обходя сайт | только один набор за раз; страницу должен отдать сам сервер, а не дорисовать скрипт |
| Один файл на весь каталог | `data.json`, DCAT, таблица CSV | забирается одной командой | растёт вместе с каталогом; у больших каталогов становится тяжёлым |
| Выгрузка по страницам | тот же DCAT, со ссылкой на следующую страницу | работает на каталоге любого размера | надо пройти все страницы; если каталог меняется во время обхода, записи могут потеряться |
| Протокол | OAI-PMH, CSW, OGC API Records | есть выборка по дате изменения | свой запрос под каждый протокол |
| Запись во внешний реестр | метаданные уходят в DataCite вместе с DOI | набор находится по идентификатору, без обхода сайта | только для наборов с DOI |

Два решения внутри этих способов стоят отдельного разговора.

**Профиль включают, а не получают «заодно».** У ckanext-dcat по умолчанию включён профиль DCAT-AP 3, а DCAT-US 3, HealthDCAT-AP и schema.org — отдельные профили, которые администратор называет в настройке. Поэтому портал на CKAN с расширением может отдавать DCAT и при этом не проходить валидатор профиля своей страны. То же у облачных сервисов: сайт на ArcGIS Hub по умолчанию отдаёт DCAT-US 1.1 и DCAT-AP 2.1.1, а ленты DCAT-US 3.0 и DCAT-AP 3.0.0 включаются отдельно.

**Выгрузка и страница — разные представления.** Одно и то же описание можно попросить в разных форматах файла: Turtle, RDF/XML, JSON-LD. Это называется согласованием содержимого: программа указывает в заголовке `Accept`, что ей нужно, или берёт адрес с нужным окончанием. Для человека это незаметно, для сборщика важно. Но страница набора и файл выгрузки живут отдельно. 13 октября 2026 года страница набора на data.gouv.fr не содержала разметки schema.org вовсе: в HTML была только ссылка на файл Turtle. Каталог отдаёт DCAT, а поисковик по данным его страницы не прочитает.

Ещё одна ловушка — страница, которую рисует скрипт. Если описание и разметка догружаются после открытия страницы, робот, который не выполняет скрипты, видит пустую оболочку. Так устроена страница набора на data.europa.eu. Подробнее — в главе [о находимости](../07-publishing/05-discoverability.md).

## Когда нужна, а когда нет

| Ситуация | Что нужно | Чем обычно закрывают |
|----------|-----------|----------------------|
| Портал, который собирает национальный или data.europa.eu | DCAT в профиле страны, без регистрации, с устойчивым адресом | ядро DKAN, udata, Huwise, Socrata, ArcGIS Hub; у CKAN — ckanext-dcat с нужным профилем |
| Наборы высокой ценности в ЕС | профиль DCAT-AP HVD поверх DCAT-AP | профиль в ckanext-dcat, форматтеры GeoNetwork, настройка ленты у Hub |
| Каталог, который должны находить поиском | разметка schema.org на странице каждого набора и карта сайта | ядро Dataverse, InvenioRDM, GeoNetwork, NADA; у CKAN — тот же ckanext-dcat |
| Геопортал в инфраструктуре страны | ISO 19115 и CSW или OGC API Records; для портала открытых данных — ещё GeoDCAT-AP | ядро GeoNetwork |
| Научный репозиторий | DataCite и OAI-PMH; schema.org — для поиска | ядро Dataverse, InvenioRDM, DSpace |
| Каталог микроданных | DDI на каждое обследование; schema.org — для поиска | ядро NADA |
| Каталог показателей | SDMX для международных партнёров | ядро .Stat Suite; у PxWeb полноценного SDMX нет |
| Каталог для машинного обучения | Croissant | ядро Hugging Face, Kaggle, OpenML; у CKAN — плагин в ckanext-dcat, у Dataverse — в ядре с версии 6.10 |
| Десяток наборов, который никто не собирает | schema.org и один файл `data.json` | статический сайт, JKAN |
| Служебная витрина для своих сотрудников | ничего | экспорт не нужен |

Разметку schema.org стоит ставить почти всем: она ничего не стоит на типовой платформе и решает, попадёт ли набор в поиск по данным. Полноценный профиль DCAT-AP нужен только тем, кого реально собирают. Для каталога из десятка наборов он избыточен — но файл со всеми описаниями полезен и ему: по нему каталог подберёт агрегатор, когда до него дойдёт очередь.

Коротко, как выглядит обоснование по шаблону [карточки решения](../06-choice/04-justifying-decisions.md):

- **Контекст.** Региональный портал открытых данных на CKAN 2.11. Национальный портал собирает регионы по DCAT-AP 3, а сотрудники просят «чтобы нас было видно в Google».
- **Варианты.** Поставить ckanext-dcat с профилем по умолчанию; включить в нём профиль DCAT-AP 3 и разметку schema.org; написать свою выгрузку в JSON «по мотивам DCAT».
- **Критерии.** Какой профиль ждёт национальный портал, попадает ли набор в поиск, сколько стоит сопровождение при обновлении CKAN.
- **Решение.** ckanext-dcat с профилем DCAT-AP 3 и плагином разметки. Свою выгрузку не писать.
- **Почему.** Расширение ведёт команда CKAN, оно проверяется на CKAN 2.10, 2.11 и 2.12. Свой JSON придётся объяснять каждому сборщику отдельно, а профиль по умолчанию может не совпасть с тем, что ждёт национальный портал.
- **Когда пересмотреть.** Если страна примет национальный профиль поверх DCAT-AP или если портал переедет с CKAN.

Три строки в таблице расходятся с тем, что обычно говорят о платформах.

**GeoNode не отдаёт DCAT.** Его каталог — это pycsw: CSW отвечает карточками ISO 19115, Dublin Core и ещё несколькими форматами, среди которых DCAT нет. Так отвечали живые установки GeoNode в Никарагуа и Боливии 13 октября 2026 года. Файл `data.json`, который реестр находит у части установок GeoNode, к ядру версии 5.1 не относится: в её коде такого адреса нет, а открывшийся файл содержал свой список полей, а не каталог DCAT-US.

**udata не размечает страницы.** data.gouv.fr на udata 17.12.1 отдаёт описание набора файлом Turtle, но в HTML страницы блока schema.org нет. Для сборщика каталог открыт, для Google Dataset Search — нет.

**У Dataverse разметка сменилась.** До версии 6.10 в страницу встраивалась schema.org, и её можно вернуть настройкой. С версии 6.10 на её месте краткая разметка Croissant: без списка файлов, зато её просит Google, чтобы набор попал в фильтр «с поддержкой Croissant». Полную разметку со списком файлов по-прежнему отдают через выгрузку.

### Что показывает реестр

По выгрузке реестра dataportals-registry (выпуск 1.27.0 от 15 октября 2026 года) хотя бы один стандартный способ отдать описания — DCAT, OAI-PMH, CSW, OGC API Records, SDMX или STAC — записан у 9 330 каталогов из 43 614, это 21%. Выгрузка DCAT есть у 5 233. Из них 3 152 отдают сразу и DCAT-US, и DCAT-AP: это в основном сайты ArcGIS Hub, у которых обе ленты включены по умолчанию.

Разметку schema.org реестр почти не записывает — таких адресов в нём 38, — поэтому её долю по реестру считать нельзя. Её видно только на самой странице.

Доля зависит от платформы сильнее, чем от желания владельца. Среди порталов открытых данных DCAT отмечен у 239 из 245 на Socrata, у 348 из 454 на Huwise, у 103 из 161 на DKAN и у 633 из 1 906 на CKAN. У собственных разработок — у 24 из 1 144. Расширение ckanext-dcat ставит треть порталов на CKAN, хотя без него каталог не попадает в сбор. Запросы — в [приложении о реестре](../12-appendices/02-using-the-registry.md#экспорт-метаданных).

### Расширения и их риски

У CKAN в ядре выгрузки описаний нет. Всю работу делает ckanext-dcat. Его ведёт команда CKAN, лицензия AGPL, последний выпуск — 2.4.4 от 11 августа 2026 года. В документации поддержка заявлена для CKAN 2.10 и 2.11, автоматические тесты идут и на 2.12. Пока поддержку 2.12 не объявили, работу расширения на этой версии проверяют на своём стенде. Методика оценки расширения — в главе [об экосистемах расширений](../05-platforms/02-extension-ecosystems.md).

Внутри одного расширения несколько плагинов, и каждый включают отдельно:

- **dcat** отдаёт каталог в RDF и читает чужие выгрузки;
- **structured_data** ставит разметку schema.org на страницу набора. Без него DCAT есть, а поисковик каталог не видит;
- **croissant** отдаёт описание для машинного обучения. Площадки в 2026 году отдают Croissant 1.0, хотя вышла версия 1.1.

Профиль по умолчанию — DCAT-AP 3. Рядом лежат профили DCAT-AP 2, DCAT-US 3, HealthDCAT-AP и schema.org. Национальный профиль пишут своим плагином поверх готового: так устроен DCAT-AP_IT. Риск здесь не в заброшенности расширения, а в настройке. Портал с расширением «для галочки» отдаёт профиль по умолчанию и не проходит проверку своего национального портала.

Отдельное расширение, ckanext-spatial, поднимает CSW через pycsw, но только для записей, собранных с других геопорталов, а не для всего каталога CKAN.

У Dataverse выгрузка DCAT — тоже расширение, и оно моложе. Экспортёр DCAT 3 от сообщества GDCC, выпуск 0.8.7 от 31 августа 2026 года, делает DCAT 3 и нидерландский профиль DCAT-AP-NL 3.0. Он рассчитан на Dataverse 6, лучше всего на 6.2 и новее, и сам помечен как прототип. Ставить его стоит тем, кто уже знает, какой профиль от них ждут.

## Как ломается: файл открывается, профиль не тот

Проверка 13 октября 2026 года. Три выгрузки прогнаны через SHACL-валидатор Европейской комиссии, профиль DCAT-AP 3.0.1, уровень базовых правил.

**data.europa.eu, набор о качестве воздуха в Бристоле.** Выгрузка Turtle прошла без ошибок. Это ожидаемо: портал сам собирает описания по DCAT-AP и сам их отдает. Зато страница набора в браузере без скриптов пуста, и разметки schema.org в ней нет. Каталог образцово открыт для сборщика и закрыт для поисковика, который читает только HTML.

**data.gov.gr, ряд наблюдений метеостанции.** Каталог на CKAN 2.11.3 с ckanext-dcat, профиль DCAT-AP 3, в описании стоят и признак набора высокой ценности, и ссылка на регламент. Валидатор нашёл две ошибки. Формат файла записан текстом «CSV», а профиль ждёт ссылку на тип из словаря. У контрольной суммы файла не указан алгоритм. Страница при этом размечена: в HTML есть блок schema.org. Выгрузка и разметка сделаны, а профиль формально не проходит из-за двух полей.

**data.gouv.fr, набор о субсидиях.** Файл Turtle открывается, но валидатор отмечает формат «xls», записанный текстом. На полной проверке добавляются издатель и частота обновления: они записаны ссылками, которые не объявлены объектами нужного типа. В HTML страницы разметки нет совсем.

Ещё четыре поломки встречаются часто.

- **Профиль по умолчанию.** Расширение включено, но отдаёт DCAT-AP 2 там, где ждут DCAT-AP 3, или DCAT-US 1.1 там, где уже принимают 3.0.
- **Выгрузка без страницы.** Сборщик каталог забирает, поисковик — нет. Так устроены udata и ArcGIS Hub.
- **Страница без выгрузки.** Разметка есть, а файла со всеми описаниями нет. Поисковик наборы найдёт, национальный портал — нет.
- **Чужое в выгрузке.** Лента ArcGIS Hub описывает всё содержимое сайта: на opendata.dc.gov в ней 1 871 запись, из которых наборами поиск считает 1 476. Сборщик, который верит ленте, опубликует у себя карты и приложения как наборы.

## Публикация без портала

Без портала описания не появляются сами: их кладёт автор. Хватает двух файлов.

**Разметка на странице набора.** Блок JSON-LD со словарём schema.org: название, описание, автор, издатель, дата, лицензия и список файлов. Готовый [шаблон](pathname:///templates/schema-dataset.jsonld) есть в книге. Его вставляют в шаблон страницы один раз, и он заполняется из полей набора.

**Файл со всеми описаниями.** Для небольшого каталога это `data.json` по схеме DCAT-US 1.1: её понимают и сборщики data.gov, и агрегаторы. JKAN собирает такой файл из страниц сам, но шаблон заполняет короткий список полей и не закрывает обязательные поля схемы. Перед сдачей сборщику файл проверяют, см. главу [о статических сайтах](../08-beyond-portals/02-static-sites.md#jkan). На своём статическом сайте его собирают скриптом при каждой сборке, иначе он устареет в день публикации второго набора.

Если набор архивируют в Zenodo, описание в DataCite туда уходит вместе с DOI, и отдельный файл DCAT для этого набора не нужен. Как устроить страницу и регистрацию в каталоге, разобрано в главе [«Как сделать публикацию находимой»](../08-beyond-portals/05-making-it-findable.md).

## Как проверить живой портал

Ручная проверка — четыре вопроса к живому каталогу:

1. Откройте страницу набора и найдите в исходном коде блок `application/ld+json` с типом Dataset. Либо вставьте адрес страницы в [проверку расширенных результатов Google](https://search.google.com/test/rich-results).
2. Найдите файл со всеми описаниями и посмотрите, какой профиль он заявляет. У DCAT-US это поле `conformsTo`.
3. Сравните числа. Наборов в выгрузке должно быть столько же, сколько в поиске на сайте.
4. Прогоните файл через валидатор нужного профиля. Для DCAT-AP это [SHACL-валидатор Европейской комиссии](https://www.itb.ec.europa.eu/shacl/dcat-ap/upload): берите проверку базовых правил той версии, которую ждёт ваш сборщик, сейчас это `dcatap.3_0_1_base`.

### Команды

Подставьте адрес портала и адрес страницы одного набора. Команды проверяют разметку, типичные адреса выгрузки и заявленный профиль.

```bash
PORTAL=https://data.gov.gr
PAGE=https://data.gov.gr/dataset/emy-station-189

# Разметка schema.org на странице набора
curl -sL "$PAGE" | grep -o '"@type": *"Dataset"' | head -1

# Файл со всеми описаниями: DCAT по страницам и data.json
curl -sI "$PORTAL/catalog.ttl" | head -1
curl -sI "$PORTAL/data.json" | head -1

# Какой профиль заявляет файл
curl -s "$PORTAL/data.json" | head -c 400
```

Дальше — адреса конкретных платформ, проверенные 13 октября 2026 года:

```bash
# CKAN с ckanext-dcat: описание одного набора в Turtle и число наборов в выгрузке
curl -sL "https://data.gov.gr/dataset/emy-station-189.ttl" | head -20
curl -s "https://data.gov.gr/catalog.ttl" | grep -E "hydra:(totalItems|lastPage)"

# udata: файл Turtle по набору и общая выгрузка
curl -sI "https://www.data.gouv.fr/api/1/datasets/slug-набора/rdf.ttl" | head -1

# Huwise: весь каталог одним файлом
curl -sI "https://opendata.paris.fr/api/explore/v2.1/catalog/exports/dcat" | head -1

# ArcGIS Hub: какая лента включена и сколько в ней записей
for V in dcat-us/1.1 dcat-us/3.0 dcat-ap/2.1.1 dcat-ap/3.0.0; do
  echo -n "$V "; curl -s "https://opendata.dc.gov/api/feed/$V.json" | jq '.dataset | length'
done

# InvenioRDM: одна запись в DCAT и в schema.org
curl -s -H "Accept: application/dcat+xml" "https://data.caltech.edu/api/records/идентификатор" | head
curl -s -H "Accept: application/ld+json" "https://data.caltech.edu/api/records/идентификатор" | head

# GeoNetwork 4.4: какие форматы отдаёт CSW
curl -s "https://sdi.eea.europa.eu/catalogue/srv/eng/csw?service=CSW&version=2.0.2&request=GetCapabilities" \
  | grep -o 'dcat[^<]*'

# Научный репозиторий: OAI-PMH
curl -s "https://dataverse.harvard.edu/oai?verb=Identify" | grep repositoryName

# Dataverse: встроенная разметка Croissant и список форматов выгрузки
curl -s "https://borealisdata.ca/api/info/exportFormats"
```

Хороший результат: блок Dataset в HTML, файл выгрузки открывается без входа, в нём заявлен нужный профиль, а валидатор не находит ошибок базового уровня. Плохой: адрес отвечает, но профиль старый, форматы записаны текстом вместо ссылок на словарь, а на странице набора разметки нет. Сводный список — в [чек-листах](../12-appendices/04-checklists.md#проверка-живого-портала).

## Что из этого следует

- Сначала узнайте, кто заберёт ваши описания и какой профиль он ждёт. Выгрузка «в DCAT вообще» этого требования не закрывает.
- Ставьте и выгрузку, и разметку. Первая кормит сборщика, вторая — поисковик, и платформы закрывают их по отдельности.
- Проверяйте выгрузку валидатором нужной версии профиля, а не только ответом сервера. Формат файла текстом вместо ссылки на словарь — типичная причина отказа.
- На CKAN всё это делает одно расширение, ckanext-dcat, но профиль и разметку включают явно. Расширение без настройки отдаёт профиль по умолчанию.
- Пишете каталог сами — заложите в задание и файл выгрузки в профиле страны, и блок schema.org в шаблоне страницы. Ни то ни другое само не появится.
