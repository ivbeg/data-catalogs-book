# Экспорт метаданных

Каталог полезен не только людям на его сайте. Другие порталы, поисковики и программы должны уметь прочитать описания наборов. Для этого каталог отдаёт метаданные в формате, который эти системы уже понимают.

Сами стандарты разобраны в главе [«Стандарты метаданных»](../07-publishing/02-metadata-standards.md). Здесь — о возможности платформы их отдавать.

## Два разных адресата

**DCAT** — словарь для обмена описаниями между каталогами. По нему национальный портал забирает региональные, а общий европейский портал — национальные. У DCAT есть профили: DCAT-AP для Европы, DCAT-US (файл `data.json`) для США, плюс национальные уточнения.

**schema.org/Dataset** — разметка прямо в HTML-странице набора. Её читают поисковики, в том числе Google Dataset Search. Это не замена DCAT: у разметки другая аудитория.

Часто нужны оба. DCAT кормит федерацию и агрегаторы, schema.org — обычный поиск.

Отраслевые форматы закрывают своих потребителей:

- геоданные — ISO 19115 / ISO 19139 и каталожный сервис CSW;
- наука — DataCite и протокол OAI-PMH;
- микроданные — DDI;
- статистика — SDMX.

## Когда это нужно

- schema.org нужна всем, кто хочет, чтобы набор находили через поисковик, а не только зайдя на сайт каталога.
- DCAT нужен, если каталог входит в федерацию или его собирает агрегатор. Для государственных порталов в ЕС это практическое требование.
- Отраслевой формат нужен, когда так устроена отрасль: геопортал в инфраструктуре INSPIRE, репозиторий в научной сети OpenAIRE, статистика для международных организаций.
- Каталогу из десятка наборов, который никто не собирает автоматически, достаточно schema.org и одного файла со всеми описаниями. Полноценный профиль DCAT-AP здесь избыточен.

Насколько экспорт важнее качества самих данных, видно по поиску. В ноябре 2024 года Google Dataset Search по русским запросам выдавал на первых местах наборы с hubofdata.ru и ngodata.ru — двух небольших общественных порталов на CKAN. Не потому, что они самые полные, а потому, что на их страницах есть разметка schema.org. Портал открытых данных Москвы data.mos.ru, крупный и рабочий, не отдавал ни schema.org, ни DCAT, и его наборов не было ни в Google Dataset Search, ни в поисковике Dateno. Так же в 2022 году выпадал портал Индии data.gov.in: обычный поиск Google его индексировал, поиск по данным — нет.

## Как это сделано в платформах

Сверено с документацией платформ и карточками программного обеспечения реестра dataportals-registry (выгрузка от 9 октября 2026 года, выпуск 1.26.0 от 6 октября 2026 года). Пометки те же, что в [сводной таблице](../12-appendices/03-platform-tables.md): ядро, расширение, нет, не проверено.

| Платформа | DCAT | schema.org | Отраслевой формат |
|-----------|------|------------|-------------------|
| CKAN | расширение [ckanext-dcat](https://docs.ckan.org/projects/ckanext-dcat/en/latest/) | расширение (тот же ckanext-dcat) | расширение (OAI-PMH) |
| DKAN | ядро | не проверено | не проверено |
| uData | ядро | не проверено | не проверено |
| Piveau | ядро | не проверено | ядро (SPARQL) |
| OpenDataSoft | ядро | не проверено | не проверено |
| Socrata | ядро | не проверено | не проверено |
| ArcGIS Hub | ядро | не проверено | ядро (OGC API Records) |
| Dataverse | нет | ядро | ядро (OAI-PMH, DataCite, Dublin Core) |
| InvenioRDM (Zenodo) | ядро | ядро | ядро (OAI-PMH и DataCite) |
| DSpace | нет | не проверено | ядро (OAI-PMH и Dublin Core) |
| GeoNetwork | ядро | ядро: JSON-LD на странице записи, с расширением Croissant | ядро (ISO 19115 и CSW); OGC API Records — расширение |
| GeoNode | ядро | не проверено | ядро (CSW, ISO 19115, OAI-PMH, WMS/WFS) |
| PxWeb | нет | нет | ядро (SDMX) |
| NADA | нет | нет | ядро (описания в духе DDI, свой API) |
| JKAN | ядро (файл `data.json`, не полный DCAT-AP) | не проверено | нет |
| Статический сайт своими руками | нет (файл кладёт автор сайта) | нет (блок в шаблоне пишет автор) | нет |

## Как проверить живой портал

Разметка для поисковиков. Откройте страницу набора и найдите в исходном коде блок `application/ld+json` с типом Dataset. Либо вставьте адрес страницы в [проверку расширенных результатов Google](https://search.google.com/test/rich-results).

Выгрузка DCAT. Проверьте, отвечает ли сайт по типичным адресам. Подставьте адрес портала вместо `https://portal.example`:

```bash
curl -I https://portal.example/data.json
curl -I https://portal.example/catalog.rdf
curl -I https://portal.example/catalog.ttl
```

Ответ `200` и тип содержимого JSON, XML или Turtle — хороший знак. Дальше файл стоит прогнать через валидатор нужного профиля (для DCAT-AP это SHACL-валидатор Европейской комиссии).

Геопортал. Запросите возможности каталожного сервиса:

```bash
curl -I "https://portal.example/csw?service=CSW&request=GetCapabilities"
```

Научный репозиторий. Идентификация OAI-PMH:

```bash
curl -I "https://portal.example/oai?verb=Identify"
```
