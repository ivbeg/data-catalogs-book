# Другие возможности

Ниже — возможности, которые часто попадают в техническое задание «по аналогии с большим порталом». У каждой есть порог, ниже которого она не нужна.

Отдельные главы для них не заведены: поиск, языки и статистика короче, чем экспорт метаданных или хранилище, а сбор чужих каталогов подробно разобран в главе [«Федерации и агрегация»](../07-publishing/03-federation-and-harvesting.md). Если какой-то из разделов разрастётся в самостоятельное решение, его стоит вынести.

## Поиск и навигация

Поиск по словам, фильтры по организации, теме и формату, на геопортале — поиск по карте.

Достаточно простого поиска, когда наборов десятки и у каждого понятное название. Отдельный поисковый движок (у CKAN это Solr) нужен, когда наборов тысячи и люди фильтруют, а не листают список.

Проверка: наберите слово из середины описания, а не только из названия. Если портал ищет лишь по названию, большинство наборов не находятся.

## Предпросмотр

Таблица, график или карта на странице набора. Это помогает человеку решить, тот ли файл он скачивает. Предпросмотр не заменяет файл и API: его нельзя процитировать и нельзя надёжно забрать программой.

У облачных платформ предпросмотр таблиц входит в сервис. У CKAN таблицу на странице показывает связка DataStore и XLoader. У Dataverse в ядре есть механизм подключения просмотрщиков (external tools), а сами просмотрщики — отдельный набор от сообщества Dataverse, dataverse-previewers. Их ставит администратор установки, и для закрытых файлов предпросмотр не показывается. Поэтому «у Dataverse есть предпросмотр» верно только для установки, где его включили: проверяйте на конкретном сайте.

## Несколько языков

Интерфейс и описания наборов. Обязательно для международной организации и для страны с несколькими официальными языками. Для одного города с одним языком перевод интерфейса не нужен.

Перевести кнопки проще, чем описания. Если метаданные ведут на одном языке, а интерфейс на двух, поиск на втором языке будет пустым.

У CKAN многоязычные поля делает расширение ckanext-fluent вместе с ckanext-scheming; оба тестируются на CKAN 2.10–2.12. У Dataverse и InvenioRDM несколько языков интерфейса включаются настройкой: переводы поставляет сообщество, администратор выбирает, какие показывать. Отдельные поля описания переводятся, если это заложено в схеме.

## Сбор чужих каталогов

Портал забирает описания из других каталогов по расписанию: из DCAT, API CKAN, CSW, OAI-PMH. Это нужно региональному или национальному порталу и любому агрегатору. Ведомственному порталу, который публикует только своё, сбор не нужен.

У CKAN каркас сбора — расширение ckanext-harvest, сбор RDF делает ckanext-dcat, сбор геокаталогов — ckanext-spatial. Кто их ведёт и с какой версией ядра они работают — в главе [про CKAN](../05-platforms/03-ckan-and-extensions.md). У Piveau сбор DCAT — основная функция ядра.

## Статистика использования

Просмотры, скачивания, вызовы API. Нужна, чтобы решать, какие наборы обновлять в первую очередь, и чтобы показать, что каталогом пользуются. Не нужна, чтобы «нарисовать большую цифру» в годовом отчёте: число наборов и число просмотров легко раздуть.

У CKAN типичный путь — расширение ckanext-googleanalytics (ведёт сообщество CKAN, тестируется на 2.10–2.12) или разбор журналов веб-сервера. У облачных сервисов статистика обычно входит в тариф. Счётчик на сайте не видит скачивания, которые идут мимо страницы, напрямую по API. Если API — главный способ доступа, считать нужно и его.

## Обратная связь

Кнопка «нашли ошибку», форма «запросите набор», витрина примеров использования. Для публичного государственного портала это способ понять спрос. Для архива, куда данные кладут по регламенту гранта, достаточно контакта в описании.

У CKAN витрину примеров делает расширение ckanext-showcase, страницы «о портале» — ckanext-pages. Оба ведёт сообщество CKAN, оба тестируются на CKAN 2.10–2.12. У ckanext-pages нет выпусков с 2023 года: его ставят из основной ветки репозитория, и при обновлении ядра это лишний шаг проверки. ckanext-showcase на CKAN 2.12 требует отдельно настроить хранилище картинок.
