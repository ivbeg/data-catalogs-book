# Метрики качества

Метрика полезна, если по ней видно, что чинить. Число наборов в подвале сайта почти никогда таким не является.

| Что меряете | Как посчитать |
|-------------|----------------|
| Полнота описаний | доля наборов, где заполнены обязательные поля: лицензия, издатель, дата, период |
| Свежесть | доля наборов, обновлённых не позже обещанного срока |
| Доступность | доля ссылок и сервисов, которые открываются; простой сайта |
| Пригодность формата | доля файлов в открытых форматах без ломаной вёрстки |
| Ясность прав | доля наборов с явной лицензией в карточке и в выгрузке |
| Машинный доступ | есть ли выгрузка всех описаний и, при большом каталоге, API |
| Совместимость | проходит ли выгрузка проверку профиля DCAT, ISO или DataCite |
| Использование | скачивания, вызовы API, ссылки из статей. Смотреть вместе, не вместо качества |

Считайте на выборке, если наборов тысячи: 30–50 карточек из разных организаций, не только свежие. Долю считают от числа наборов в выборке, не от числа заполненных полей в одной идеальной карточке.

## Чем считать

Половину таблицы можно посчитать программой. Остальное — глазами.

| Что проверяет | Инструмент |
|---------------|-----------|
| Выгрузка соответствует DCAT-AP | [валидатор DCAT-AP](https://www.itb.ec.europa.eu/shacl/dcat-ap/upload) на платформе тестирования Еврокомиссии |
| Описания слоёв и сервисы соответствуют INSPIRE | [INSPIRE Reference Validator](https://inspire.ec.europa.eu/validator/) |
| Разметка schema.org на странице набора читается | [Schema Markup Validator](https://validator.schema.org/) и [проверка расширенных результатов Google](https://search.google.com/test/rich-results) |
| Запись научного репозитория похожа на FAIR | [F-UJI](https://www.f-uji.net/) — по идентификатору или адресу записи |
| Полнота и доступность описаний в европейской федерации | [MQA на data.europa.eu](https://data.europa.eu/mqa/) — если портал уже отдаёт описания в европейский каталог |
| Ссылки на файлы открываются | любой проверщик ссылок или короткий скрипт, который запрашивает каждый адрес |

MQA полезно разобрать как образец формулы. Поля описания разложены по четырём измерениям FAIR: находимость, доступность, совместимость, повторное использование. Вес поля зависит от того, насколько оно важно в DCAT-AP 3: обязательное — 1, рекомендуемое — 0,5, необязательное — 0,25. Отдельно проверяют, что ссылка на файл отвечает, а формат взят из общего справочника. Своя формула не обязана быть такой же. Но веса по обязательности поля и проверка живых ссылок — разумная основа.

Портал на CKAN можно посчитать без отдельных инструментов, через его API. Команда ниже берёт 200 наборов и считает три доли: с лицензией, хотя бы с одним файлом в открытом формате и обновлённые за последний год.

```bash
PORTAL=https://open.canada.ca/data
curl -s "$PORTAL/api/3/action/package_search?rows=200&start=0" \
  | jq '.result.results as $r | ($r | length) as $n | {
      datasets: $n,
      with_license: ([$r[] | select((.license_id // "") != "" and .license_id != "notspecified")] | length / $n),
      open_format: ([$r[] | select(any(.resources[]; (.format // "" | ascii_upcase) as $f
                      | ["CSV","JSON","XML","GEOJSON","GPKG","PARQUET"] | index($f)))] | length / $n),
      updated_last_year: ([$r[] | select(.metadata_modified > "2025-10-11")] | length / $n)
    }'
```

Для большого каталога запустите команду несколько раз с разным `start`, чтобы выборка не состояла из одних первых наборов. Поле `metadata_modified` показывает дату правки карточки, а не файла. Свежесть данных точнее проверять по дате у самого файла или по полю периодичности, если портал его ведёт.

## Что не стоит делать главной цифрой

**Число наборов.** Его поднимают, режа один ряд на файлы. Каталог из 50 честных наборов полезнее каталога из 5 000 пустых карточек. Если число всё же нужно для отчёта, рядом ставят два других: долю наборов меньше 100 строк и общий объём данных в сжатом виде. Как их посчитать и как выглядят порталы, где число наборов врёт, — в главе [о самоаудите](./04-self-audit.md#проверка-по-существу).

Насколько число наборов обманывает, видно по объёму. В феврале 2022 года полная выгрузка российского data.gov.ru дала 26,5 тысячи наборов и 29 ГБ, причём 6,8 ГБ из них — один разовый слепок адресного реестра, а 14,5% наборов весили меньше килобайта. У гуманитарного портала HDX при сопоставимом числе наборов (около 31 тысячи) объём по выкачанной пятой части оценивался примерно в терабайт, у британского data.gov.uk одни только CSV без сжатия занимали 222 ГБ. Разница в объёме в десятки раз при одинаковом счётчике означает, что каталоги публикуют разное.

Поэтому показатель «опубликовать N наборов» в государственной программе без перечня того, какие именно наборы нужны, ничего не меряет: такую цифру собирают за день из однострочных таблиц. Осмысленная цель — список конкретных наборов, например [наборов высокой ценности](../02-data/01-what-is-published.md), и доля опубликованных из него.

**Число просмотров главной страницы.** Оно не видит тех, кто забирает выгрузку. Если API — основной вход, считают и его.

**Балл, который набирают пустые поля.** Валидатор профиля проверяет, что поле есть. Он не проверяет, что в описании не скопирован текст соседнего набора. Поэтому к автоматической оценке добавляют просмотр нескольких карточек глазами.

## Признаки жизни

Отдельная задача — понять, жив ли портал вообще. Для чужого каталога, на который собираетесь опираться, и для своего, если его давно никто не открывал, хватает пяти проверок:

- дата последнего **нового** набора, а не последней правки карточки;
- дата последней новости или записи в журнале изменений;
- есть ли регулярно обновляемые ряды и совпадает ли дата обновления с обещанной периодичностью;
- доля ссылок на файлы, которые открываются;
- не пропали ли разделы, которые были раньше: план публикации, статистика использования, запросы данных.

Когда в 2022 году с data.gov.ru пропала страница статистики посещений, а план публикации data.mos.ru удалили ещё в 2020 году, это было заметнее любого рейтинга. Хороший признак обратного — набор, который обновляется каждый день и которым явно пользуются. Для государственного портала есть простой исторический тест: публиковал ли он данные о COVID-19, пока они были нужны всем. Таиландский data.go.th публиковал ежедневно, российский data.gov.ru — нет.

Пороги «хорошо / плохо» задают под свою задачу. Для начала достаточно увидеть, что лицензия есть меньше чем у половины наборов: это уже очередь на исправление, а не повод спорить о формуле.
